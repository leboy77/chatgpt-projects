# Visual Forge 团队看板设计

## 1. 目标

把公司同事使用插件生成的图片统一上报到内部服务器，提供网页端看板进行登录、汇总、筛选、预览和下载。

目标规模：约 25 人。

## 2. 当前 MVP 形态

当前实现位于：

```text
..\dashboard
```

MVP 采用：

- Python 3.10 标准库 HTTP 服务。
- SQLite 数据库。
- 本地文件存储原图。
- Pillow 生成 WebP 缩略图。
- 无 npm 构建的前端看板。

这样在尚未安装 Docker 的机器上也能直接运行。后续升级到 PostgreSQL + MinIO 时，API 保持不变。

## 3. 架构

```text
同事电脑插件
  ↓ 任务完成后上报
内部看板服务器
  ├─ 登录与权限
  ├─ 任务 API
  ├─ 图片上传
  ├─ 缩略图生成
  └─ SQLite + 本地文件
  ↓
网页端看板
  ├─ 统计总览
  ├─ 任务筛选
  ├─ 图片预览
  └─ 成员管理
```

## 4. 部署

### 本地运行

```powershell
cd .\dashboard
python server.py --host 0.0.0.0 --port 8766
```

### Docker

```powershell
docker compose up -d --build
```

访问：

```text
http://<内网服务器IP>:8080
```

默认管理员：

```text
用户名：admin
密码：admin123
```

正式部署时必须修改默认密码和 Token Secret。

## 5. 数据表

```text
users
projects
project_members
tasks
artifacts
```

核心字段：

- `tasks.id`：插件任务 ID，幂等键。
- `tasks.group_id`：多版本任务链归属。
- `tasks.module`：产品裂变、商品配色、印花套图、Logo 多色、Logo 重绘。
- `artifacts.sha256`：文件校验。
- `artifacts.thumb_key`：缩略图存储路径。

## 6. API

```text
POST /api/v1/auth/login
GET  /api/v1/auth/me

GET  /api/v1/projects
POST /api/v1/projects
GET  /api/v1/users
POST /api/v1/users

POST /api/v1/tasks
GET  /api/v1/tasks
GET  /api/v1/tasks/{id}
GET  /api/v1/tasks/{id}/artifacts
POST /api/v1/tasks/{id}/artifacts
POST /api/v1/tasks/{id}/status

GET  /api/v1/artifacts/{id}/download
GET  /api/v1/artifacts/{id}/thumbnail

GET  /api/v1/stats/overview
```

上传方式：`multipart/form-data`。

## 7. 插件同步方案

后续在插件中新增同步模块：

1. 配置看板地址和登录 Token。
2. 任务完成后读取任务记录、图片和清单。
3. 创建或更新任务。
4. 上传图片文件。
5. 更新任务状态。
6. 离线时保存在本地上报队列，联网后补传。

## 8. 后续升级

当 25 人规模稳定运行后，将：

- SQLite 升级为 PostgreSQL。
- 本地文件升级为 MinIO。
- 增加 Redis/RQ 异步缩略图任务。
- 增加 Nginx/Traefik 和 HTTPS。
- 增加插件自动同步，移除手动上传测试入口。
