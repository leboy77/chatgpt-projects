# Visual Forge 变更记录

本文件记录产品、技术、接口、归档和验收口径的变化。版本号按组件分别记录；后端包版本与扩展版本不要求相同。

## 2026-11-19 · 0.13.1 商品类目枚举与上衣提示词

### 扩展

- 版本：`0.13.1`
- 新增统一商品类目枚举：`auto`、`lower`、`upper`、`dress`、`set`、`other`。
- 产品裂变、印花套图和产品视频新增“商品类目”下拉框。
- 自动模式会从用户描述中识别常见上装、下装、连衣类和套装关键词。
- 模板新增 `category_name`、`category_print_area`、`category_base_surface`、`category_protected_area`、`category_model_region` 变量。
- 发送前强制追加“【商品类目约束】”；选择上装时只处理上装正背面和袖子印花区域，并明确禁止改成裤子、裤装、下装或裙装。
- 删除产品裂变默认提示词和底布约束中的硬编码“裤子、裤底、裤腿”正向描述。
- 商品类目写入产品裂变、印花套图和产品视频任务，支持加载、复制、记忆恢复和队列执行。
- 印花套图和产品视频归档清单记录 `category`。
- 修改产品裂变、Logo 重绘和产品视频中含裤子专属示例的输入提示文案。

### 影响

- 用户可以明确选择上衣、裤子、连衣裙或套装，不再默认把所有服装当作裤子处理。
- 自动模式能处理描述中明确提到上装或下装的任务；没有关键词时使用通用商品约束。
- 直接发送用户提示词模式仍保持原文，不自动添加类目包装。

### 自动化测试

- 60 项单元测试全部通过。
- 新增上衣类目测试，确认 Prompt 包含上装正背面与袖子印花区域，且不包含“只改变裤子印花”的正向指令。
- `full-flow-virtual.js` 通过：产品裂变、印花套图和产品视频均以 `category=upper` 保存并执行。
- 完整虚拟流程确认实际发送给 Muse 的 Prompt 同时包含“商品类目：上装”和“商品类目是上装”的类目锁。
- 生成 `visual-forge-muse-0.13.1.zip`，包内 49 个文件，`manifest.json` 版本核验为 `0.13.1`。

### 人工验收

- 分别选择上装、下装、连衣类、套装运行产品裂变，确认生成的提示词和结果与所选类目一致。
- 选择上装运行印花套图和产品视频，确认不会出现裤腿、裤底或裤子印花等正向指令。
- 保存任务后刷新页面，确认商品类目可恢复并参与队列执行。

## 2026-11-18 · 0.13.0 产品视频生成与真人出镜不露脸

### 扩展

- 版本：`0.13.0`
- 新增“产品视频”模式和独立提示词模板“产品视频 · 商品展示”。
- 上传 1 张商品主图，通过 Muse 生成商品展示视频；支持约 5、8、10 秒和 9:16、1:1、16:9。
- 展示方式支持 `product`、`worn_no_face` 和 `mixed`；后两种只允许颈部以下入镜。
- 新增不可被模板覆盖的“真人出镜硬约束”：脸部必须完全出画，禁止正脸、侧脸、完整头部、头像和脸部特写。
- 新增 `VF_MUSE_GENERATE_VIDEO` 和 `VF_FETCH_VIDEO` 消息；内容脚本支持识别 `<video>`、`source` 和视频附件链接。
- 单个视频默认等待 10 分钟；启用 5 分钟无响应兜底时使用 30 分钟总等待。
- 每个视频请求失败自动重试 1 次；仍失败时记录失败请求，任务完成后可单独重试。
- 视频返回后立即在挂件播放，并复用即时下载机制保存到浏览器下载目录。
- 新增 `product_video_generate` 任务和 Job，可保存、加载、按 X 复制、排队、暂停和重试。
- 视频 Job 不进行图片转码，保留 Muse 返回的 MP4、WebM、MOV 或 M4V；单个后台视频下载上限 100MB。
- 产品视频归档目录包含源图、视频、`manifest.json`、`manifest.csv` 和 README，清单记录展示方式、时长、比例、请求数、成功/失败数及面部策略。
- 链接模式对产品视频写入 `视频链接.txt` 和 `视频链接.json`，不写视频文件。

### 影响

- 产品视频成为第六个可排队任务模式，产品裂变和其他既有模式继续沿用原行为。
- 用户可以选择完全不出现真人的商品视频，也可以让模特上身；所有真人方案都强制不露脸。
- 视频生成能力和实际出片速度仍取决于 Muse 账号、服务端模型和当前对话容量。

### 自动化测试

- 58 项单元测试全部通过。
- `background-smoke.js` 通过，并验证 `VF_FETCH_VIDEO` 返回视频类型和二进制内容。
- `full-flow-virtual.js` 通过：产品视频任务保存、统一队列分派、Muse 视频捕获、即时下载和授权目录归档均正常。
- 完整流程归档 `产品视频_2026-11-18_15-20-57/product-video-01.mp4`，视频资产类型为 `video/mp4`。
- 实际发送给虚拟 Muse 的 Prompt 包含颈部以下、脸部完全位于画面外、禁止正脸和侧脸。
- 完整流程即时下载调用由 19 次增加到 20 次。
- 生成 `visual-forge-muse-0.13.0.zip`，包内 49 个文件，`manifest.json` 版本核验为 `0.13.0`。

### 人工验收

- 待安装 `0.13.0` 后在真实 Muse 账号验证视频生成入口、返回格式和视频播放。
- 使用“模特上身 · 严格不露脸”生成至少 1 个视频，确认全片没有脸部、侧脸或完整头部。

## 2026-11-17 · 0.12.18 Muse 每批返回后即时下载

### 扩展

- 版本：`0.12.18`
- 新增“Muse 返回后立即下载”开关，默认开启，配置保存到 `chrome.storage.local.immediateDownload`。
- 产品裂变、Logo 重绘、商品配色和印花套图在 Muse 每批返回并通过当前批次校验后，立即调用浏览器下载。
- 即时下载路径为浏览器默认 Downloads 下的 `VisualForge自动保存\YYYY-MM-DD\任务名`；文件名包含时间、批次和全局输出序号。
- 使用 `conflictAction: "uniquify"` 处理同名文件，不覆盖既有下载；Blob object URL 在下载发起后最多 60 秒释放。
- 开启“仅下载图片链接”时不执行即时图片下载，最终归档仍只写链接清单。
- 即时下载失败只在当前会话提示一次，不中断 Muse 生成、预览、IndexedDB 保存或授权目录归档。
- `manifest.json` 新增 `downloads` 权限。

### 影响

- Muse 每次返回一批图片后，用户无需等待整条任务结束即可在浏览器下载目录取得图片。
- 即时下载与最终任务归档是两份独立结果；即使任务最终归档失败，已经完成的即时下载仍保留。
- 最终授权目录归档逻辑保持不变，任务结束后仍会写入用户选择的归档根目录。

### 自动化测试

- 55 项单元测试全部通过。
- `background-smoke.js` 后台扩展桥接测试通过。
- `full-flow-virtual.js` 完整虚拟流程通过，模拟触发 `chrome.downloads.download` 共 19 次。
- 完整流程同时确认最终任务目录、清单和图片仍正常归档，即时下载不替代最终归档。
- 生成 `visual-forge-muse-0.12.18.zip`，包内 49 个文件，`manifest.json` 版本核验为 `0.12.18`。

### 人工验收

- Muse 返回一批图片后，在浏览器 `Downloads\VisualForge自动保存` 下确认立即出现对应文件。
- 关闭“Muse 返回后立即下载”后，确认任务执行期间不再产生即时下载，但最终归档正常。
- 开启“仅下载图片链接”后，确认不产生即时图片文件，只保留链接清单。

## 2026-11-17 · 0.12.16 产品裂变背景处理选项

### 扩展

- 版本：`0.12.16`
- 产品裂变新增“背景处理”选项：默认“随印花改变背景”，也可选择“保持原主图背景”。
- 默认 Prompt 通过 `background_instruction` 区分两种模式。
- “随印花改变背景”改写为强制语义：背景必须真正改变为与当前印花风格一致的新场景、纹理、色彩、道具和光影，不能仅做轻微调色。
- “保持原主图背景”要求严格保持原背景、墙面、地面、空间结构、色调、道具、光线和阴影。
- 背景模式写入任务配置、任务详情和提示词记忆，刷新或加载任务后恢复。
- 自定义模板没有背景变量时，发送前自动补充对应背景指令。

### 影响

- 用户可以直接控制产品裂变是否更换背景，不再依赖模糊的“协调背景”描述。
- 默认结果更容易出现明显风格化背景，同时仍保持原主图构图和商品位置。
- 随机裤底与背景处理互不混淆：裤底仍随机改变，背景由该选项决定。

### 自动化测试

- 验证默认背景 Prompt 使用“必须真正改变为”，保持模式使用原背景约束。
- 验证产品任务默认保存 `background_mode=match`。
- `full-flow-virtual.js` 完整流程通过，任务记录恢复背景模式。

## 2026-11-16 · 0.12.15 随机裤子底布与风格化背景

### 扩展

- 版本：`0.12.15`
- 修正“随机底色”的对象：随机颜色现在作用于裤子本体的底布，不再只改变图片背景。
- 每张 Prompt 明确要求把裤子原有白色底布改为随机非白色，印花叠加在裤底上。
- 图片背景不再要求纯色，改为根据当前印花风格生成协调的场景、纹理、色彩和光影。
- 背景仍保持与原主图相同的构图、机位、裁切和商品位置。
- 单图分配一个随机裤底色；多图分别为每张分配不同裤底色。
- `pickBackgroundColors()` 重命名为 `pickPantsBaseColors()`，避免再次混淆裤底和图片背景。

### 影响

- 结果不会再大量出现“白色裤子 + 纯色背景”，而是彩色裤底 + 与印花协调的背景。
- 真正被随机化的是裤子底布颜色和印花方向；背景由印花风格决定。
- 商品结构、版型、构图和平面印花约束保持不变。

### 自动化测试

- 55 项单元测试全部通过。
- 验证空描述 Prompt 包含随机裤底颜色，并禁止停留在白色底布。
- 验证每批 4 张获得 4 个不同非白裤底色。
- 验证背景 Prompt 为风格化背景而不是纯色。
- `full-flow-virtual.js` 完整流程通过。
- 生成 `visual-forge-muse-0.12.15.zip`，内容与 `extension` 目录一致。

### 人工验收

- 留空描述生成一批图片，检查裤子本体不再是纯白底布。
- 检查每张背景与对应印花风格协调，而不是单一纯色背景。
- 检查商品构图、机位和位置仍与原主图一致。

## 2026-11-16 · 0.12.14 原主图默认链式与参考图降级约束

### 扩展

- 版本：`0.12.14`
- 任务链模式默认改为“每一版都使用原主图（推荐）”，避免连续生成累积版型、结构和印花漂移。
- “上一版结果作为下一版主图”保留为手动选项，并标注可能累积变形。

- 原有已保存的 `chain_mode=previous` 任务仍按原配置执行，不会自动改写用户历史配置。
- 参考素材解析更符合普通印花生产能力，减少把“立体视觉”误实现成真实工艺。

### 自动化测试

- 55 项单元测试全部通过。
- 验证任务默认 `chain_mode=original`。
- 验证简单模板包含原构图、只换裤子印花、随机背景、工厂约束和参考图降级规则。
- `full-flow-virtual.js` 完整流程通过，模板页显示 7 项，保存任务记录为 `original`。
- 生成 `visual-forge-muse-0.12.14.zip`，内容与 `extension` 目录一致。
