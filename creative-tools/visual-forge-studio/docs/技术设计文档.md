## 3. Manifest 与权限

固定权限：

- `activeTab`
- `storage`
- `tabs`
- `downloads`
- `unlimitedStorage`

固定 host permissions：

- `https://muse.ai/*`
- `https://*.muse.ai/*`
- Muse 图片相关 CDN 域名。

可选 host permissions：

- `https://*/*`
- `http://*/*`

远程模型保存时，选项页对用户填写的 API origin 调用：

```js
chrome.permissions.request({ origins: [`${origin}/*`] })
```

用户拒绝授权时不会保存远程模型配置。

Manifest 不再声明：

- `http://127.0.0.1/*`
- `http://localhost/*`

## 4. 初始化

### 4.1 模型配置

`chrome.storage.local.modelConfig`：

```json
{
  "provider": "mock",
  "baseUrl": "https://api.openai.com/v1",
  "model": "gpt-image-1",
  "apiKey": ""
}
```

`provider`：

- `mock`：Canvas 本地占位图。
- `openai`：OpenAI 兼容生成接口。

### 4.2 目录授权

File System Access API 的 Handle 不能通过 `chrome.storage` 正确持久化，因此存入 IndexedDB：

```text
settings:
  key = "archiveDirectory"
  value = FileSystemDirectoryHandle
```

挂件嵌入 Muse 页面后处于跨域 iframe。为保证目录选择稳定：

1. 点击挂件“选择”时打开顶层扩展页 `directory.html`。
2. 用户在该页选择“选择新目录”或“重新授权当前目录”。
3. “选择新目录”直接调用 `showDirectoryPicker({mode:"readwrite"})`。
4. Handle 写入 IndexedDB。
5. 返回挂件后通过 `focus` 事件刷新授权状态。

权限状态：

- `granted`：可直接写。
- `prompt`：需要用户确认。
- `denied`：需重新选择目录。

重新授权行为：

1. 目录页初始化时预取已保存 Handle 和权限状态。
2. “重新授权当前目录”按钮在点击回调中同步调用原 Handle 的 `requestPermission({mode:"readwrite"})`。
3. 在 `requestPermission` 之前不插入 IndexedDB、状态查询或其他 `await`，保证浏览器仍有用户手势。
4. 重新授权成功不打开系统文件夹选择器。
5. `denied` 或原 Handle 不可用时提示使用“选择新目录”。

脚本在非交互阶段不弹权限窗口。权限失效时任务仍保留，任务卡显示“重新授权并保存”。

浏览器权限面板中若选择“每次访问时都允许”，该目录在扩展重载和 Muse 页面刷新后仍保持 `granted`；若选择“仅这次访问时允许”，下次重载会重新进入 `prompt`。

旧实现把“选择新目录”和“重新授权”混在一个按钮中，并且 `showDirectoryPicker()` 返回后又跨越异步写入和查询调用 `requestPermission()`，容易丢失用户手势。0.12.6 起两者完全拆分：`reauthorizeSavedDirectory()` 只接受预取 Handle，立即 request；`chooseNewDirectory()` 始终直接打开 picker，返回后只用 `queryPermission()` 校验结果，不再二次 request。商品配色、Logo 多色、Logo 重绘、印花套图和产品裂变均不把该权限作为生成前置条件。

### 4.3 提示词模板与记忆开关

`chrome.storage.local` 保存：

```json
{
  "promptTemplates": {
    "copy": "产品裂变完整模板",
    "product_color": "商品配色完整模板",
    "product_color_batch": "商品配色多图完整模板",
    "logo_design": "Logo 重绘完整模板",
    "logo_design_batch": "Logo 重绘多图完整模板",
    "pattern_single": "印花逐张完整模板",
    "pattern_batch": "印花批量完整模板",
    "video_showcase": "产品视频完整模板"
  },
  "copyDirectPrompt": false,
  "copyMemoryEnabled": true,
  "immediateDownload": true
}
```

默认模板由 `prompt-templates.js` 与产品裂变的 `local-core.js` 导出。提示词模板页展示 8 个 Prompt，产品裂变只保留一套“固定构图换印花”模板；商品配色、Logo 重绘、印花和产品视频模式保留各自模板。内容脚本接收 Side Panel 传入的当前模板后替换变量。

- `{{instruction}}`：去除“变为/改成”等前缀后的用户裂变描述。产品裂变模板可以不包含该变量。
- `{{index}}`、`{{total}}`：当前序号和总输出数。
- `{{direction}}`：当前印花方向标识。
- `{{visual_instruction}}`：对应的印花和场景说明。
- `{{visual_instruction}}` 由风格包和当前请求序号选择；`yabi_moto` 包含 32 个 Y2K、机车、朋克、机能和暗黑潮流方向。
- `{{color_list}}`、`{{color_count}}`：商品配色多图模式的色号清单和本批输出数。
- `{{output_count}}`、`{{request_index}}`：Logo 重绘多图模式的单次输出数和请求序号。
- 商品配色、Logo 重绘和两种印花模式分别使用模板页列出的功能专用变量。
- `{{duration_seconds}}`、`{{aspect_ratio}}`、`{{presentation_instruction}}`、`{{request_index}}`、`{{request_count}}`：产品视频的时长、比例、展示方式和请求序号。
- `{{category_name}}`、`{{category_print_area}}`、`{{category_base_surface}}`、`{{category_protected_area}}`、`{{category_model_region}}`：商品类目上下文。
- `ensureVideoNoFaceConstraint()` 在发送前强制检查“【真人出镜硬约束】”标记；用户模板没有该标记时自动追加颈部以下、脸部完全出画、禁止正脸和侧脸的约束。

商品类目由 `prompt-templates.js` 的 `PRODUCT_CATEGORIES` 统一枚举：

```text
auto | lower | upper | dress | set | other
```

- `productCategoryOptions()`：向 Side Panel 的三个类目下拉框提供选项。
- `resolveProductCategory()`：在 `auto` 模式下根据用户描述识别上衣、下装、连衣类或套装。
- `productCategoryValues()`：返回类目名称、印花区域、底布区域、保护区域和模特穿着区域。
- `ensureProductCategoryConstraint()`：追加不可省略的“【商品类目约束】”，防止旧模板或用户模板继续把上装写成裤子。

`local-core.js` 中 `buildCopyVariationPrompts()` 和 `buildCopyBatchPrompts()` 新增第六个参数 `categoryValue`。底布随机色仍由 `pickPantsBaseColors()` 生成，但提示词中统一称为当前类目的“底布/表面底色”，不再写死“裤子底布”。产品裂变任务把类目写在顶层 `category` 和 `options.category`，印花套图与产品视频写入 `options.category`。

空模板或超过 12000 字符时拒绝保存；产品裂变不再要求包含 `{{instruction}}`。产品裂变开启 `copyDirectPrompt` 后，`buildDirectCopyPrompts()` 只把用户输入作为最终 Prompt，Muse 适配器也不再添加前置或后置包装。

`immediateDownload` 默认值为 `true`。用户可在任务控制栏关闭；开启“仅下载图片链接”时即使该开关开启，也不创建即时图片下载。

## 5. IndexedDB

数据库：`visualforge-extension`，版本 `3`。

### 5.1 jobs

主键 `id`，索引 `created_at`。

```json
{
  "id": "32位id",
  "kind": "product_color_finalize",
  "status": "queued|running|succeeded|failed",
  "progress": 0,
  "message": "",
  "error": null,
  "archive_error": null,
  "options": {},
  "outputs": [],
  "export_path": null,
  "created_at": "ISO",
  "updated_at": "ISO",
  "started_at": null,
  "finished_at": null
}
```

### 5.2 assets

主键 `id`，索引 `job_id`。

保存：

- 图片、JSON、CSV 的 Blob。
- 名称、MIME、字节数、宽高、SHA-256。
- 缩略图 Data URL。
- 颜色、ΔE、QA、遮罩来源和变体类型。
- 可选的 `muse_url`：Muse 返回的原始图片 URL，用于链接清单和仅链接导出。

任务记录只保存缩略图和元数据，完整图片从 `assets` 读取。

### 5.3 settings

主键 `key`，当前保存归档目录 Handle。

### 5.4 tasks

主键 `id`，索引 `created_at` 和兼容旧数据的 `group_id`。

一条记录代表任意模式的一次完整配置。各模块共用 `tasks` store，通过 `module` 分派，避免拆库和迁移多套生命周期逻辑：

```json
{
  "id": "任务ID",
  "module": "product_color|logo_recolor|logo_image_generate|pattern_transfer|product_generate|product_video_generate",
  "category": "auto|lower|upper|dress|set|other",
  "request_mode": "stable|batch",
  "batch_size": 4,
  "output_count": 4,
  "request_count": 10,
  "main_image": {
    "name": "输入图片文件名",
    "type": "image/png",
    "size": 543566,
    "relative_path": "refs/main.png",
    "blob": "Blob"
  },
  "files": ["印花参考图等额外 Blob 记录"],
  "options": {
    "colors": [],
    "region": "whole",
    "sku": "",
    "request_mode": "stable",
    "batch_size": 4
  },
  "status": "pending",
  "last_job_id": null,
  "error": null,
  "created_at": "ISO",
  "updated_at": "ISO"
}
```

所有涉及本地文件的图片记录都保存名称、MIME、大小、相对路径和 Blob；因此刷新后仍可恢复输入并执行任务。`options` 保存模式专属参数，顶层保留产品裂变旧字段以兼容 0.11.x 记录。

“保存当前配置”只写入一条记录。产品裂变的 `request_count` 表示 Muse 对话轮数，`output_count` 表示每轮要求返回的图片数（1-4），两者乘积为预计总图片数。每一轮只提交一次 Muse 对话，但最终只创建一个 `product_generate` Job、一个历史记录和一个归档目录。列表操作支持所有模块的加载、按 X 批量复制、运行和删除。

产品视频任务的 `options` 额外保存 `presentation_mode`、`duration_seconds`、`aspect_ratio`、`request_count`、`prompt` 和 `prompt_template`；展示方式限定为 `product|worn_no_face|mixed`，默认请求 1 个视频，每次请求固定输出 1 个 Muse 视频附件。

“另存为新任务（不覆盖）”清空当前保存任务的 ID 关联，但保留表单配置；下一次保存会生成新 task ID。导出方式 `files/links_only` 属于运行时选项，不写入 tasks 配置，因此队列执行时使用当前界面开关。

数据库从版本 `2` 升级到 `3` 时，具有同一 `group_id` 的旧版逐版本任务会合并为一条产品裂变配置，`output_count` 取原记录数量；已有单条记录保持兼容。

### 5.5 prompt_memories

主键 `id`，索引 `updated_at`。记录主图 Blob、裂变描述、模板、输出张数、引擎、链式模式、尺寸、货号、使用次数和时间。相同主图与配置通过 SHA-256 生成稳定 ID，只更新使用次数；最多保留最近 20 条。

### 5.6 重载恢复

挂件初始化先调用 `recoverInterrupted()`：

- 扫描 `queued/running`。
- 标记为 `failed`。
- 扫描 `tasks.status=running` 并标记为 `failed`。
- 错误：`扩展重载或浏览器重启，任务已中断，请重新开始`。
- `succeeded/failed` 历史保留。

## 6. 任务执行

### 6.1 任务类型

| kind | 执行器 |
| --- | --- |
| `logo_recolor` | `local-core.recolorLogo` |
| `logo_image_generate` | `local-core.finalizeLogoDesign` |
| `logo_image_recolor` | 0.7.x 旧记录兼容，不再由当前 UI 创建 |
| `product_generate` | `local-core.buildProductVariants` + provider |
| `product_video_generate` | Muse 视频附件收尾、媒体清单和目录归档 |
| `product_color_finalize` | `local-core.finalizeProductColors` |
| `pattern_batch_finalize` | `local-core.finalizePatternBatch` |

### 6.2 创建

`VisualForgeJobs.create(kind, options, files, control)`：

1. 生成 32 位任务 ID。
2. 写入 `queued`。
3. 通过 `setTimeout(..., 0)` 启动执行器。
4. 返回任务记录，挂件立即显示任务卡。

### 6.3 完成

1. 每个输出转为独立 Asset。
2. 计算 SHA-256 和缩略图。
3. 写 `manifest.json` 和 `manifest.csv`。
4. 写入任务 `outputs`。
5. 标记 `succeeded`。
6. 请求归档目录权限并将 Asset 写入任务包。
7. 归档失败不删除生成结果，任务保留 `archive_error`。

#### 6.3.1 Muse 返回后即时下载

`immediateDownloadFiles(files, context)` 在 Side Panel 收到一次 Muse 图片或视频回复并通过当前校验后调用。产品裂变、Logo 重绘、商品配色、印花套图和产品视频均在媒体返回后立即调用；Logo 多色由扩展本地处理，不涉及 Muse，因此不触发即时下载。

- 开关状态读取 `immediateDownloadInput`，持久化配置为 `chrome.storage.local.immediateDownload`，默认开启。
- 每次收到已经通过校验的图片或视频后立即调用 `chrome.downloads.download()`，不等待整条任务结束。
- 文件路径为 `VisualForge自动保存/YYYY-MM-DD/<任务名>/<时间>_批次NN-NN_<序号>_<文件名>`，相对浏览器默认 Downloads 目录。
- `filename` 中任务名、时间和原文件名均经清洗；`conflictAction: "uniquify"` 避免覆盖同名文件，`saveAs: false` 避免每张图片弹出保存框。
- 每个 Blob 创建独立 object URL；下载回调完成后最多 60 秒撤销 URL。
- 下载失败只在当前会话提示一次，不中断 Muse 生成、预览、IndexedDB 保存或最终授权目录归档。
- 开启 `links_only` 时立即返回，不创建图片文件下载；最终归档只写链接清单。
- 即时下载是浏览器目录中的保护副本，不改变 `local-jobs.js` 和 `local-archive.js` 的最终任务归档流程。即使最终归档失败，已完成的即时下载仍保留。

当 `export_mode=links_only` 且 Job 中存在 `muse_url` 时，归档器只写 `图片链接.txt`、`图片链接.json` 和 README，不写图片 Blob；没有 Muse URL 的本地模式自动回退到普通图片归档。IndexedDB 仍保留处理所需的 Blob，以免破坏校色和任务预览。

### 6.4 暂停

暂停仅存在于挂件执行上下文：

- 商品配色：每个 Muse 色号完成后检查。
- 印花：每张参考图提交前检查。
- Logo 重绘：每次批量或逐张 Muse 请求前检查。
- 产品裂变：每张图片生成前检查。

继续后处理下一个待执行项。当前正在进行的网络请求不会取消。

### 6.5 任务队列

“一键排队全部任务”读取 `tasks`，按 `created_at` 从早到晚排序后通过 `executeStoredTask()` 按 `module` 顺序分派：

1. 每个任务恢复自己的输入 Blob、模板、请求方式和模式参数。
2. 当前任务全部图片生成并写入 IndexedDB 后，才开始下一任务。
3. 单条任务失败时任务状态写为 `failed`，队列继续执行后续任务。
4. 暂停队列后，当前正在生成的图片完成后停止；跨任务继续时仍保持暂停，继续后处理下一个待执行项。
5. 队列实时统计成功、失败、自动保存和未保存任务数。
6. 自动保存数来自该任务最后创建的本地 Job `export_path`；无权限时生成仍成功，但计入未保存。
7. 队列结束后“重试失败任务”只使用本次失败的 task ID 重新排队，不重复运行成功任务。
8. 队列依赖当前挂件页面保持打开；浏览器关闭或页面刷新会中断当前任务，未开始任务保留为待运行。

分派表：

| module | 执行入口 |
| --- | --- |
| `product_color` | `runProductColors()` |
| `logo_recolor` | `runLogoJob("recolor")`，本地执行 |
| `logo_image_generate` | `runLogoJob("batch")` |
| `pattern_transfer` | `runPatternTransfer()` |
| `product_generate` | `runLogoJob("generate")` |
| `product_video_generate` | `runProductVideo()` |

所有模式都不在生成前调用归档目录预检。生成完成后，本地 Job 尝试归档；目录缺失、权限失效或用户未授权时只写 `archive_error`，任务结果仍保留在 IndexedDB，可在恢复授权后再次保存。

`autoArchiveUnsavedJobs()` 在目录权限恢复、切回 Muse、完成目录授权或队列结束时扫描最近 100 条成功但无 `export_path` 的 Job，并自动补归档，不要求用户逐卡点击。

任务卡复制次数 X 为任意正整数，无产品上限。每次复制生成独立 `id`、独立时间戳和 `pending` 状态；批量复制本身不会自动运行任务。

## 7. 图像处理

### 7.1 Canvas 基础

- `createImageBitmap` 解码图片。
- `canvas.drawImage` 做尺寸适配。
- `ImageData` 逐像素处理。
- `canvas.toBlob("image/png")` 输出。
- 所有内部任务不在 Python 和本机 API 中运行。

### 7.2 Logo 背景

1. 读取 RGBA。
2. 若存在透明像素，默认保留原 Alpha。
3. 无透明通道时，从边界种子检测接近角落背景色的连通区域。
4. 四邻域 BFS 将边缘背景设为透明。
5. 保留商品内部白色和封闭细节。
6. 按 Alpha 边界裁切，保留 12px。

### 7.3 Logo 换色

创建目标色 RGBA 图层，并使用原 Logo Alpha。抗锯齿半透明边缘不会变成硬边。

### 7.3.0 商品配色请求

- 逐色稳定模式每轮把 1 张主图和 1 张色卡附加给 Muse，使用 `VF_MUSE_GENERATE_COLOR`。
- 多色批量模式把主图和最多 4 张色卡按顺序附加，使用 `VF_MUSE_GENERATE_COLOR_BATCH`。
- 批量 Prompt 列出每张色卡的 HEX、颜色描述和输出序号，要求 Muse 返回与色卡数量完全一致的独立商品图。
- Side Panel 校验返回数量，并计算各输出 SHA-256；数量不符或重复时不使用本批任何结果，改为逐色单请求。
- 逐色保底仍可捕获 `Delivery not confirmed`、超时或单色失败，并保留 `failedProductColors` 供局部重试。

### 7.3.1 Logo 重绘

1. 上传完整商品主图和“新 Logo 设计要求”。
2. 逐张稳定模式使用 `VF_MUSE_GENERATE_LOGO_DESIGN`；多图模式使用 `VF_MUSE_GENERATE_LOGO_DESIGN_BATCH`。
3. Prompt 要求删除所有旧 Logo，在原位置和透视下替换为一套新设计。
4. 非 Logo 区域要求保持商品、印花、背景、构图、裁切和光影不变。
5. `request_count` 表示请求次数，`output_count` 表示每批数量（1-4 张）；目标总数为两者乘积，界面实时显示计算口径。
6. 批量请求数量不符、重复、投递失败或超时时，自动把该轮降级为逐张请求。
7. 所有新增图片归一化到主图尺寸，并由一个 `logo_image_generate` 本地 Job 与源图写入同一任务目录。
8. “保存 / 更新”复用当前 task ID；“新增 Logo 重绘任务（不覆盖）”调用 `saveCurrentModeTask(..., {forceNew:true})`，忽略当前 ID 并生成新任务。

### 7.4 商品遮罩

优先级：

1. 用户遮罩：有 alpha 用 alpha，否则用亮度。
2. 目标色遮罩：HSV 接近目标色的区域。
3. 差异遮罩：主图和 Muse 结果的像素差，阈值 26。
4. 区域主色遮罩：`whole/upper/lower` 内按颜色聚类和中心评分。

低于 0.2% 覆盖率判定失败，提示用户提供遮罩。

### 7.5 精确保留光影

对高饱和且非极黑/极白目标：

- 对遮罩内 RGB 通道求中位值。
- 按目标通道与源通道中位值比例缩放。
- 保留原像素之间的相对明暗和纹理。

对白、黑和低饱和目标：

- 以目标明度替换主体明度。
- 使用 HSV 色相/饱和度。
- 混合 18% 目标明度，避免过曝和死黑。

最终使用 96% 遮罩强度合成。

### 7.6 ΔE2000

转换链：

```text
sRGB -> Linear RGB -> XYZ(D65) -> Lab -> CIEDE2000
```

采样：

- 遮罩值达到 96 的像素。
- 去除遮罩内亮度最低 15% 和最高 10% 的极端像素。
- 对 RGB 通道取中位值。

分别计算：

- `muse_delta_e`：Muse 原图。
- `delta_e`：本地校正结果。

质检：

```text
deltaE <= 3   pass
deltaE <= 5   review
deltaE > 5    retry
```

### 7.7 印花收尾

扩展不负责重新绘制印花。它：

1. 校验生成图数量。
2. `cover-fit` 到白底图尺寸。
3. 按参考图编号输出。
4. 生成 4 列对比图。
5. 写清单和归档。

商品纹理、褶皱和印花真实感由 Muse 依据提示词生成。

## 8. 文案生图（图生图）

### 8.1 Prompt 规划

文案生图同时支持两个引擎：

- `muse`：默认引擎，通过 Muse 页面图生图。
- `model`：OpenAI 兼容 `/images/edits`。

两个引擎共用可编辑模板；开启直接发送模式时不使用模板。

主模板固定为：

```text
1 张商品主图
+ 保持原图构图、机位、裁切、商品位置、比例、版型、面料、褶皱、五金、光影和非裤子区域
+ 只改变裤子表面的平面印花和配色
+ 可选用户补充描述
+ 按商品类目随机非白色底布
+ 与印花风格协调的非纯色背景
+ 工厂平面印花约束
+ 禁止拼图、文字和水印
```

`instruction` 在模板模式下允许为空。直接发送模式仍要求完整 Prompt。

### 8.1.1 工厂平面印花约束

所有模板模式在发送前都会强制包含 `PRINT_ONLY_CONSTRAINT`：

- 商品本体只允许改变表面的平面印花、图案、配色和平面视觉纹理。
- 必须沿用原商品的面料、版型、厚度、软硬、光泽、结构和全部物理细节。
- 禁止新增或改变任何物理结构、配件、口袋、绑带或装饰件。
- 印花必须像普通染料墨水一样哑光平涂、清晰套色、无光泽、无浮凸、无立体感，只呈现二维矢量或网点图形。
- 禁止任何依赖特殊材料、特殊油墨或后整理工艺的视觉效果。
- 参考图只贡献印花图案、线稿、配色和平面明暗，不贡献立体结构、真实材质或特殊工艺。
- 背景也使用普通哑光布景，不渲染特殊表面效果。

亚比机车、街头、暗黑机能和全部风格混合库的正向描述已删除金属、反光、铬、镭射、全息、亮片、镜面、珠光和皮革等词。相关方向改用冷灰、平涂、矢量线稿和网点表达。即使用户自定义模板删除约束，`ensurePrintOnlyConstraint()` 也会在发送前补回。直接发送模式仍严格使用用户原文，不自动追加模板。

同日补丁继续清理了 `closeup_flash` 中的“材料反射”，改为“平面色块层次”，并移除“半透明叠色、发光线条、材质异常道具”等残留在正向描述中的强质感措辞。

Muse 引擎使用 `VF_MUSE_GENERATE_COPY_BATCH`，每轮向 Muse 附 1 张主图和一条包含 1-4 个方向的批量 Prompt，要求同一次回复返回指定数量的独立图片。

每个结果在进入本地任务前计算 SHA-256。若与本次任务已有图片重复，自动附加“更换印花母题、图案排列和随机底布颜色，但不得改变机位、裁切和商品位置”的重试指令，最多请求 3 次；仍重复时进入失败列表。

`buildCopyVariationPrompts()` 接受 `style_pack`：

- `auto`：默认，根据用户描述选择方向；未命中亚文化关键词时使用 16 个摄影语言方向。
- `yabi_moto`：32 个亚比机车方向。
- `street`：涂鸦、滑板、赛车、档案网版、科技、嘻哈、朋克和未来运动。
- `dark_tech`：全黑机能、警示、隐身、能量、碳纤维、故障、装甲和夜间机能。
- `all`：合并全部风格包，共 72 个去重方向，适合大请求量时最大化差异。
- `balanced`：旧版综合商业视觉，保留兼容。

`buildCopyBatchPrompts()` 将每轮的 `visual_instruction` 渲染为多个编号方向，并注入 `{{batch_count}}`。若用户模板没有该变量，系统会追加“本批必须输出 N 张独立商品图”的硬性返回要求，但不会覆盖用户对风格和摄影语言的自定义内容。

“全部风格混合”通过 `shuffleDirections()` 使用 Fisher–Yates 算法随机打乱方向数组。每次调用 `resolveCopyStylePack()` 都创建新数组，不修改 `COPY_STYLE_PACKS.all` 原始顺序，因此每个任务/请求批次都有不同的起始方向，同时仍保证 72 个方向不重复。

产品裂变界面将 `stylePack=all` 设为默认推荐项，并置于下拉列表首位。`auto` 智能导演继续保留为需要优先听从提示词时的备用选项。

`pickProductBaseColors()` 从 10 个非白色中随机挑选当前批次的目标底布颜色；`pickPantsBaseColors` 保留为旧调用别名。Prompt 通过商品类目上下文输出“上装底布”“下装底布”或通用“商品表面底色”。单图写入一个底布颜色；多图每个画面分别分配。即使自定义模板没有引用 `visual_instruction`，发送前也会追加类目底布和背景约束。

产品裂变新增 `background_mode`：

- `match`：默认。Prompt 必须使用“背景必须真正改变为与当前印花风格一致的新场景”，禁止保留原背景或仅做轻微调色。
- `keep`：严格保持原主图的背景、墙面、地面、空间结构、色调、道具、光线和阴影。

模式写入任务与提示词记忆，并传给 `buildCopyBatchPrompts()`。默认模板通过 `{{background_instruction}}` 渲染当前模式；自定义模板缺少该变量时自动追加背景指令。

主界面不再提供“提示词模板版本”下拉框，只保留一套产品裂变模板；旧 `copy_*` 常量仅用于兼容历史数据，不显示在模板页。

### 8.2 单任务多输出

产品裂变按“一条配置一条任务”执行：

```text
保存/更新一条 tasks 配置
→ 发起第 1 轮 Muse 对话并等待 1-4 张
→ 发起第 N 轮对话（可暂停）
→ 创建一条 product_generate Job
→ 本地生成清单并归档到同一个任务目录
```

每轮图片捕获后立即更新挂件“Muse 最近返回”预览。某轮数量不足、图片重复或投递失败时重试该轮，最多 3 次。

链式输入模式：

- `original`：默认，每一张都使用用户最初上传的主图，避免版型、结构和印花连续累积漂移。
- `previous`：可选，上一版生成图作为下一版输入，适合需要连续演化的实验链。

任务参数记录：

- `task_id`
- `prompt_template`
- `output_count`
- `request_count`
- `total_requests`
- `total_images`
- `prompts[]`
- `base_prompt`
- `chain_mode`
- `provider`

全部生成图作为同一 Job 的 `files[1..N]` 进入 `finalizeCopyVariants()`，各图仍保留自己的 `direction` 和完整 Prompt。任务失败时当前配置保留为 `failed`，重试从整条任务重新运行。

`request_count` 是 Muse 对话轮数，`output_count` 是每轮要求返回的图片数；`total_images = request_count × output_count`。请求次数不设置产品上限，代码仅拒绝非正整数和超过 JavaScript 安全整数范围的值。

### 8.2.1 产品视频

产品视频使用独立 `product_video_generate` 任务模块和 Job：

1. Side Panel 校验 1 张商品主图、展示方式、时长、画面比例和请求次数。
2. `buildProductVideoPrompt()` 渲染 `video_showcase` 模板，再调用 `ensureVideoNoFaceConstraint()` 强制补回真人出镜不露脸约束。
3. 每个请求通过 `VF_MUSE_GENERATE_VIDEO` 发送主图、完整 Prompt、时长、比例和请求序号。
4. 内容脚本从提交后新增的 `video`、`source` 或视频下载链接中识别 Muse 结果，等待源 URL 稳定 1.8 秒。
5. `fetchMuseVideo()` 优先在 Muse 页面读取 Blob；跨域失败时通过 `VF_FETCH_VIDEO` 交给后台下载，单个视频上限 100MB。
6. 返回文件根据响应类型和 URL 保留 `.mp4`、`.webm`、`.mov` 或 `.m4v`，不进行图片缩放或 Canvas 重编码。
7. 每个请求失败自动重试 1 次；仍失败则记录 `failed_requests`，不阻止其他请求继续。
8. 成功视频和主图一起进入一个 `product_video_generate` Job；清单记录时长、比例、展示方式、请求数、成功/失败数和 `visible_model_must_not_show_face`。

产品视频默认等待 10 分钟；开启“5 分钟无响应自动继续”后沿用 30 分钟总预算。它不启用图片专用的 20 秒纯文本“重新生成”，避免把较长的视频渲染过程误判为文本失败。

### 8.3 模型请求

```http
POST {baseUrl}/images/edits
Authorization: Bearer {apiKey}

```

表单字段：

```text
model=gpt-image-1

n=1
size=1024x1024
quality=high

```

响应支持：

- `data[0].b64_json`
- `data[0].url`

每张图片单独请求并携带同一张商品主图。超时 180 秒。

### 8.4 演示模型

`mock` 会对上传主图进行解码，并把它放入按 Prompt 哈希生成的不同场景背景中。它确保界面和任务链路真实消费主图，但不代表真实 AI 图生图质量。

## 9. Muse 自动化

### 9.0 挂件尺寸与界面缩放

- `content.js` 在 Muse 页面创建 `#vf-widget-shell`，提供北、南、东、西和四个角的 8 个 `.vf-widget-resize` 拖拽把手。
- 最小尺寸为 `340×420`，最大尺寸随浏览器视口限制；拖拽结束后将 `left/top/width/height` 写入 `localStorage.visualForgeWidgetSize`，同时保留独立的位置记忆。
- 缩放期间 Shell 设置 `data-resizing=true`，临时禁用 iframe 指针事件，避免跨域 iframe 抢占拖拽。
- 外层旧拖拽遮罩改为 `pointer-events:none`，标题栏拖动由 Side Panel 通过 `VF_WIDGET_DRAG_*` 消息完成，不再遮挡 A−/A+ 和设置按钮。
- Side Panel 使用 `--vf-ui-scale` 同时缩放布局与字体；默认 `1.1`，范围 `0.85-2.0`，步长 `0.05`。
- `chrome.storage.local.interfaceScale` 保存字号比例；A−/A+、点击百分比复位和 Ctrl/⌘ + 鼠标滚轮共用同一缩放函数。

### 9.1 指令

`content.js` 捕获 Enter 和表单 submit，只处理 `/vf` 开头文本。普通 Muse 消息不拦截。

### 9.2 DOM 查找

- 输入框：可见且可编辑的 `textarea`、`contenteditable`、`role=textbox`。
- 附件：表单内或页面最后一个图片 file 输入。
- 发送：`data-testid`、`aria-label`、`title`、中文“发送”或 submit。
- 结果图：Muse attachment presentation 或 generated-image 容器。

### 9.3 防串图

提交前记录已有图片 DOM 集合和可见 Assistant 文本计数，提交后只取新增图片和新增回复：

- 单图默认等待 90 秒。
- 批量默认等待 120 秒。
- 开启“5 分钟无响应自动继续”时，总等待预算保持 30 分钟。
- 批量图片 URL 必须稳定 1.8 秒。
- 返回数量必须等于参考图数。
- 不满足时不映射，抛出错误并自动降级。
- `Delivery not confirmed` 立即结束当前等待。
- 新增回复明确指出当前图片/批次失败时，先等待 15 秒补图；仍无结果立即抛出失败。

### 9.3.1 回复分类

`muse-response.js` 为纯函数分类器：

- `continue`：匹配“是否继续、要不要继续、Continue?”，由自动回复逻辑处理。
- `blocked`：匹配“没做出来、生成失败、暂时做不了、换新对话、先做第N个、你看怎么安排”等明确失败或流程选择文案。
- `neutral`：其他新增文字，不改变等待状态。

Side Panel 只扫描提交后新增的可见文本，并用文本出现次数与提交前快照做差，避免历史失败消息误判。`blocked` 回复会停止 5 分钟“继续”重发器，等待短宽限后让当前颜色、参考图或批次进入失败列表，上层循环继续下一项。

### 9.3.2 容量不足自动新对话

- `muse-response.isCapacityBlocked()` 识别“图片太多、生成数量过多、队列已满、达到上限、对话记录超过上限、聊天太长、请新开对话、too many images、context limit、quota exceeded”等容量文案。
- 内容脚本在普通失败前缀上增加 `VF_MUSE_CAPACITY:`，明确该失败可通过新会话恢复。
- `muse-response.js` 导出 `MUSE_FRESH_THREAD_URL=https://muse.ai/thread/new`。Side Panel 的 `sendTabMessage()` 捕获该前缀后调用 `chrome.windows.create()` 打开该空白新对话；首页 `https://muse.ai/` 会恢复 Main chat，不能用于容量恢复。
- 新标签页最多等待 15 秒，通过 `VF_PING` 确认内容脚本加载完成后，重试当前未被完整接收的请求。
- `preferredMuseTabId` 保存新对话标签页；之后所有任务请求自动重定向到该标签页，即使上层循环仍持有旧 tab ID。
- 10 分钟内最多自动打开 2 个恢复窗口，避免账号级容量限制导致无限弹窗；新版窗口仍提示容量不足时，把 `VF_MUSE_CAPACITY` 错误交回当前模式，跳过该项并继续队列。

### 9.3.3 滚动、重渲染与虚拟化

Muse 消息列表会随滚动重新挂载或移除节点，直接依赖当前可见 DOM 会造成漏图和把历史图误判成新图。

- 内容脚本安装独立 `MutationObserver`，图片节点一旦插入或 `src` 变化就加入 `trackedGeneratedImages` 账本。
- 账本最多保留 500 个 Image 引用；即使图片随后滚出视口或从 DOM 删除，引用及已加载 URL 仍可继续处理。
- 生成图片识别不再要求元素当前位于可视区域，只要求未通过 `display:none/visibility:hidden` 隐藏，并具有生成图附件容器。
- 单图等待新增 `existingSources` URL 集合；批量等待启用相同过滤。Muse 重挂载历史图片时，不会将其当成本次新结果。
- Assistant 失败/继续文本和 `Delivery not confirmed` 也改为 DOM 显示状态判断，不依赖元素是否在视口内。

未采用 fetch/XHR 注入：Muse 的生成接口、响应体和图片 URL 映射属于私有实现，注入主世界脚本会带来接口变更、流式响应和 CSP 兼容风险。DOM 生成图片账本不依赖私有网络协议，同时覆盖当前滚动/虚拟化问题。

### 9.3.4 纯文本自动重新生成

任务控制栏新增 `autoRegenerateTextOnly`，默认关闭，保存到 `chrome.storage.local`，并随每次 `VF_MUSE_*` 请求传给内容脚本。

- 只处理提交后新增的非进度文本；“正在生成、处理中、请稍候”等文字不会触发。
- 文本稳定 20 秒且仍无新增图片时，第一次自动向 Muse 发送“重新生成”。
- 发送后重新建立 Assistant 文本 baseline；第二次仍只有文字、没有图片时抛出 `VF_MUSE_TEXT_ONLY_FAILED:`。
- 自动继续询问优先交给现有继续逻辑；容量不足回复优先交给新窗口恢复逻辑。
- 输入框已有用户草稿时不覆盖，直接让当前项失败。
- 商品配色、Logo 重绘、印花套图沿用逐项失败列表；产品裂变收到文本二次失败后跳过该轮，不让外层重复三轮重试。
- 产品裂变 Job 记录 `successful_images`、`failed_images`、`failed_requests` 和 `failed_variants`；部分成功时任务状态为失败但保留已生成结果。

### 9.4 自动继续

侧边栏“自动回复继续”开关存入 `chrome.storage.local.autoContinueEnabled`，每次 Muse 生成消息携带 `autoContinue`。

- 仅在当前插件生成请求等待期间启动 `MutationObserver`。
- 启动时记录已有确认文案，避免回复历史消息。
- 只匹配新增 assistant 文案中的“是否继续”“是否需要继续”“continue?”等明确询问。
- 优先点击文案附近的“继续”按钮；找不到按钮时，在输入框为空的前提下填入并发送“继续”。
- 单次生成最多自动回复 20 次，两次回复至少间隔 1.8 秒；任务结束立即停止监控。
- 独立“5 分钟无响应自动继续”开关开启时，每轮等待启动 5 分钟计时器；没有结果且输入框为空时发送“继续”，发送后重新计时。
- 启用无响应兜底时，图片等待总超时从 4-5 分钟延长到 30 分钟，避免超时早于兜底重试。
- 关闭开关会向当前 Muse 页面发送 `VF_SET_AUTO_CONTINUE(enabled:false)`，立即停止后续自动回复。

### 9.5 Muse 返回图预览

内容脚本捕获并回传图片后，Side Panel 立即把 Blob 加入 `state.museReturnedImages`，在“Muse 最近返回”区域显示缩略图，不等待本地 Job 完成。预览保留当前会话最近 24 张；同一批次还会调用 `immediateDownloadFiles()` 写入浏览器 `Downloads\VisualForge自动保存`。原始图片继续由 Muse 对话保留，归档图片继续写入 IndexedDB 和授权目录。

#### 9.5.1 产品视频捕获

- `trackedGeneratedVideos` 保存 `<video>` 的稳定源 URL 和 poster，最多 100 项；`trackedGeneratedVideoLinks` 保存带 `.mp4/.webm/.mov/.m4v` 的生成附件链接。
- 视频源优先读取 `video.currentSrc`、`video.src` 或内部 `source[src]`；提交前建立 URL baseline，只接收新增源，避免把历史视频当成当前结果。
- `MutationObserver` 监听 `src`、`href` 和 `poster` 变化；即使视频随后滚出视口或从 DOM 移除，已登记 URL 仍可继续下载。
- Side Panel 收到视频 Blob 后使用 `<video controls muted playsInline>` 在“Muse 最近返回”区域播放，并立即调用 `immediateDownloadFiles()`。
- 链接模式仍复用最终归档链接文件；产品视频的链接文件使用“视频链接”名称，不写 MP4 Blob。

### 9.6 图片链接导出

- 内容脚本在单图、多图、商品配色、Logo 重绘和印花返回 payload 中附加 Muse 原始 URL。
- Job 参数保存按生成顺序排列的 `muse_image_urls`，本地 Job 将 URL 映射到 `muse_raw`、`logo_design`、`pattern_transfer` 或 `product_variant` Asset。
- 任务卡显示“下载图片链接”，下载 UTF-8 TXT；授权目录链接模式写 TXT 和 JSON。
- Muse 临时 URL 可能过期，链接模式不承诺长期可用；需要长期保留时关闭该开关并导出实际图片。

## 10. 印花 ZIP 编排

1. 过滤非图片和单张大于 24MB 的文件。
2. 按 `webkitRelativePath` 排序。
3. 不截取参考图总数；例如 201 张有效图片会全部进入后续批次。
4. 每批达到用户设置的 1-4 张或原始大小接近 24MB 时切组。
5. `zip-builder.js` 生成 ZIP。
6. 压缩后超过 25MB 时二分继续拆分。
7. 单文件 ZIP 仍超限则跳过。
8. 目录已授权时预留唯一顶层目录；未授权时生成确定性 `archive_group_name`，授权恢复后各批次仍写入同一根目录。
9. 每个内部批次使用同一 `archive_group_name`。

## 11. 归档

### 11.1 目录命名

```text
模块名[_货号]_YYYY-MM-DD_HH-mm-ss
```

归档时间固定使用 `Asia/Shanghai`，不跟随 BitBrowser 代理配置中的浏览器时区。

普通任务在首次归档时创建唯一目录。印花任务在目录已授权时先预留唯一目录；未授权时先记录同一 `archive_group_name`，待补存时再创建并复用该目录，保证多批次共享同一根。

产品裂变的一条配置可能生成多张图片，但只创建一个普通任务目录；目录内的图片共享同一份清单。

产品视频使用 `产品视频[_货号]_YYYY-MM-DD_HH-mm-ss`。`extensionFor()` 识别 `video/mp4`、`video/webm` 和 `video/quicktime`，没有文件名后缀时分别补 `.mp4`、`.webm`、`.mov`；视频文件保持原始字节，不转码。

### 11.2 普通任务

文件：

- 源图。
- 生成图片。
- 对比图。
- `manifest.json`。
- `manifest.csv`。
- `README.txt`。

### 11.3 印花任务

```text
根目录/
├─ 生成图/
└─ 拼图与清单/
```

生成图与清单位于同级目录。批次图片和清单均带 `批次NN_`。

### 11.4 写入安全

- 只使用用户授权根 Handle。
- 子目录和文件名经清洗。
- 不通过网页传入任意绝对路径。
- 不删除授权目录中的既有文件；同名文件重写前由任务目录隔离。

### 11.5 仅链接归档

```text
任务目录/
├─ 图片链接.txt
├─ 图片链接.json
└─ README.txt
```

印花使用共享任务目录时，链接文件增加 `批次NN_` 前缀。该模式不会写入源图、生成图、对比图或图片清单。

产品视频在链接模式下写入 `视频链接.txt`、`视频链接.json` 和 README，不写 MP4/WebM/MOV 文件。

## 12. 扩展消息

| 消息 | 用途 |
| --- | --- |
| `VF_COMMAND_FROM_MUSE` | 内容脚本把 `/vf` 指令发给扩展 |
| `VF_PANEL_COMMAND` | background 通知挂件执行指令 |
| `VF_TAKE_PENDING_COMMAND` | 挂件读取暂存指令 |
| `VF_CLEAR_PENDING_COMMAND` | 清除暂存指令 |
| `VF_FETCH_IMAGE` | 后台下载 Muse CDN 图片 |
| `VF_FETCH_VIDEO` | 后台下载 Muse CDN 视频，上限 100MB |
| `VF_MUSE_GENERATE_VIDEO` | Side Panel 请求内容脚本发送主图并等待 Muse 视频 |
| `VF_HEALTH` | 兼容的健康/模型状态查询 |
| `VF_GET_DEFAULTS` | 读取模型配置 |
| `VF_SAVE_MODEL_SETTINGS` | 旧兼容入口，正式 UI 直接写 storage |

任务 CRUD、暂停和归档不再经过 background 或本机 API，而是在挂件内直接执行。

## 13. 错误处理

| 错误 | 处理 |
| --- | --- |
| 目录未选择 | 不阻止生成；Job 记录 `archive_error`，恢复授权后自动补存 |
| 目录权限失效 | 保存结果，任务卡提供重新授权 |
| 模型域名未授权 | 设置页阻止保存远程配置 |
| 模型请求失败 | 任务失败，错误写入任务记录 |
| Muse 投递失败 | 当前色/参考图失败，可局部重试 |
| Muse 明确拒绝或要求人工选择 | 15 秒补图宽限后快速失败当前项，停止自动“继续”，执行下一项 |
| Muse 当前对话图片过多/队列已满 | 自动打开新 Muse 窗口并重试；最多 2 次，仍失败则跳过当前项 |
| Muse 未返回可播放视频 | 当前请求自动重试 1 次；仍失败则记录失败请求并继续其他视频 |
| 视频文件超过 100MB | 当前请求失败；不会写入不完整文件 |
| 即时下载失败 | 当前会话提示一次；不中断生成、预览、IndexedDB 保存和最终归档 |
| 批量返回数量异常或重复 | 不映射本批，自动改为逐张/逐色/逐参考图请求 |
| 所有 Logo 失败 | 任务失败 |
| Logo 重绘要求为空 | 阻止提交并提示填写新 Logo 设计描述 |
| Logo 重绘 Muse 返回失败 | 当前 Logo 任务失败，源图保留并可重试 |
| 商品遮罩覆盖不足 | 提示提供遮罩 |
| 浏览器重载 | 进行中任务标记中断 |

## 15. 运维

### 15.1 更新扩展

1. 替换 `extension` 目录中的文件。
2. 在 `chrome://extensions` 点击扩展“重新加载”。
3. 刷新 Muse 页面。
4. 进入目录授权页重新授权。
5. 必要时重新保存模型配置。

### 15.2 定位问题

- 挂件状态显示“配置错误”：检查模型设置或 storage。
- 目录显示“尚未选择”：进入授权页选择。
- 目录显示“需要重新授权”：打开授权页确认。
- Muse DOM 错误：刷新页面，确认已登录。
- 任务历史消失：确认没有切换浏览器 Profile 或卸载扩展。
- 归档失败：检查目录是否被移动、删除或权限被撤销。

## 16. 安全与已知风险

- API Key 存于 `chrome.storage.local`，不属于安全密钥库。
- 可选 host permission 允许扩展访问用户授权的模型域名。
- 扩展不自动登录 Muse，不读取普通对话。
- Muse 图片下载只允许指定 CDN。
- 用户授权目录之外不执行写入。
- MV3 后台和挂件都可能被浏览器生命周期终止。
- 大图逐像素处理依赖浏览器内存；超大素材应分批。

## 17. 已停用的本地架构

`../backend/` 中的 Python 服务曾负责：

- HTTP API。
- SQLite 队列。
- Pillow 图像处理。
- Python 模型 provider。
- 桌面归档。

从扩展 `0.4.0` 起，这些能力在扩展内重新实现。保留 Python 项目不会影响扩展运行，但不再是必需的。
