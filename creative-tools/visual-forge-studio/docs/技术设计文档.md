## 3. Manifest 与权限

固定权限：

- `activeTab`
- `storage`
- `tabs`
- `unlimitedStorage`

固定 host permissions：

- `https://muse.ai/*`
- `https://*.muse.ai/*`
- Muse 图片相关 CDN 域名。

可选 host permissions：

- `https://*/*`
- `http://*/*`

远程模型保存时，选项页对用户填写的 API origin 调用：

```js
chrome.permissions.request({ origins: [`${origin}/*`] })
```

用户拒绝授权时不会保存远程模型配置。

Manifest 不再声明：

- `http://127.0.0.1/*`
- `http://localhost/*`

## 4. 初始化

### 4.1 模型配置

`chrome.storage.local.modelConfig`：

```json
{
  "provider": "mock",
  "baseUrl": "https://api.openai.com/v1",
  "model": "gpt-image-1",
  "apiKey": ""
}
```

`provider`：

- `mock`：Canvas 本地占位图。
- `openai`：OpenAI 兼容生成接口。

### 4.2 目录授权

File System Access API 的 Handle 不能通过 `chrome.storage` 正确持久化，因此存入 IndexedDB：

```text
settings:
  key = "archiveDirectory"
  value = FileSystemDirectoryHandle
```

挂件嵌入 Muse 页面后处于跨域 iframe。为保证目录选择稳定：

1. 点击挂件“选择”时打开顶层扩展页 `directory.html`。
2. 用户在该页点击按钮。
3. 调用 `showDirectoryPicker({mode:"readwrite"})`。
4. Handle 写入 IndexedDB。
5. 返回挂件后通过 `focus` 事件刷新授权状态。

权限状态：

- `granted`：可直接写。
- `prompt`：需要用户确认。
- `denied`：需重新选择目录。

脚本在非交互阶段不弹权限窗口。权限失效时任务仍保留，任务卡显示“重新授权并保存”。

## 5. IndexedDB

数据库：`visualforge-extension`，版本 `1`。

### 5.1 jobs

主键 `id`，索引 `created_at`。

```json
{
  "id": "32位id",
  "kind": "product_color_finalize",
  "status": "queued|running|succeeded|failed",
  "progress": 0,
  "message": "",
  "error": null,
  "archive_error": null,
  "options": {},
  "outputs": [],
  "export_path": null,
  "created_at": "ISO",
  "updated_at": "ISO",
  "started_at": null,
  "finished_at": null
}
```

### 5.2 assets

主键 `id`，索引 `job_id`。

保存：

- 图片、JSON、CSV 的 Blob。
- 名称、MIME、字节数、宽高、SHA-256。
- 缩略图 Data URL。
- 颜色、ΔE、QA、遮罩来源和变体类型。

任务记录只保存缩略图和元数据，完整图片从 `assets` 读取。

### 5.3 settings

主键 `key`，当前保存归档目录 Handle。

### 5.4 重载恢复

挂件初始化先调用 `recoverInterrupted()`：

- 扫描 `queued/running`。
- 标记为 `failed`。
- 错误：`扩展重载或浏览器重启，任务已中断，请重新开始`。
- `succeeded/failed` 历史保留。

## 6. 任务执行

### 6.1 任务类型

| kind | 执行器 |
| --- | --- |
| `logo_recolor` | `local-core.recolorLogo` |
| `logo_color_batch` | 逐文件调用 `recolorLogo` |
| `product_generate` | `local-core.buildProductVariants` + provider |
| `product_color_finalize` | `local-core.finalizeProductColors` |
| `pattern_batch_finalize` | `local-core.finalizePatternBatch` |

### 6.2 创建

`VisualForgeJobs.create(kind, options, files, control)`：

1. 生成 32 位任务 ID。
2. 写入 `queued`。
3. 通过 `setTimeout(..., 0)` 启动执行器。
4. 返回任务记录，挂件立即显示任务卡。

### 6.3 完成

1. 每个输出转为独立 Asset。
2. 计算 SHA-256 和缩略图。
3. 写 `manifest.json` 和 `manifest.csv`。
4. 写入任务 `outputs`。
5. 标记 `succeeded`。
6. 请求归档目录权限并将 Asset 写入任务包。
7. 归档失败不删除生成结果，任务保留 `archive_error`。

### 6.4 暂停

暂停仅存在于挂件执行上下文：

- 商品配色：每个 Muse 色号完成后检查。
- 印花：每张参考图提交前检查。
- 多 Logo：每个 Logo 前检查。
- 产品裂变：每张图片生成前检查。

继续后处理下一个待执行项。当前正在进行的网络请求不会取消。

## 7. 图像处理

### 7.1 Canvas 基础

- `createImageBitmap` 解码图片。
- `canvas.drawImage` 做尺寸适配。
- `ImageData` 逐像素处理。
- `canvas.toBlob("image/png")` 输出。
- 所有内部任务不在 Python 和本机 API 中运行。

### 7.2 Logo 背景

1. 读取 RGBA。
2. 若存在透明像素，默认保留原 Alpha。
3. 无透明通道时，从边界种子检测接近角落背景色的连通区域。
4. 四邻域 BFS 将边缘背景设为透明。
5. 保留商品内部白色和封闭细节。
6. 按 Alpha 边界裁切，保留 12px。

### 7.3 Logo 换色

创建目标色 RGBA 图层，并使用原 Logo Alpha。抗锯齿半透明边缘不会变成硬边。

### 7.4 商品遮罩

优先级：

1. 用户遮罩：有 alpha 用 alpha，否则用亮度。
2. 目标色遮罩：HSV 接近目标色的区域。
3. 差异遮罩：主图和 Muse 结果的像素差，阈值 26。
4. 区域主色遮罩：`whole/upper/lower` 内按颜色聚类和中心评分。

低于 0.2% 覆盖率判定失败，提示用户提供遮罩。

### 7.5 精确保留光影

对高饱和且非极黑/极白目标：

- 对遮罩内 RGB 通道求中位值。
- 按目标通道与源通道中位值比例缩放。
- 保留原像素之间的相对明暗和纹理。

对白、黑和低饱和目标：

- 以目标明度替换主体明度。
- 使用 HSV 色相/饱和度。
- 混合 18% 目标明度，避免过曝和死黑。

最终使用 96% 遮罩强度合成。

### 7.6 ΔE2000

转换链：

```text
sRGB -> Linear RGB -> XYZ(D65) -> Lab -> CIEDE2000
```

采样：

- 遮罩值达到 96 的像素。
- 去除遮罩内亮度最低 15% 和最高 10% 的极端像素。
- 对 RGB 通道取中位值。

分别计算：

- `muse_delta_e`：Muse 原图。
- `delta_e`：本地校正结果。

质检：

```text
deltaE <= 3   pass
deltaE <= 5   review
deltaE > 5    retry
```

### 7.7 印花收尾

扩展不负责重新绘制印花。它：

1. 校验生成图数量。
2. `cover-fit` 到白底图尺寸。
3. 按参考图编号输出。
4. 生成 4 列对比图。
5. 写清单和归档。

商品纹理、褶皱和印花真实感由 Muse 依据提示词生成。

## 8. 产品文生图

### 8.1 Prompt 规划

当前使用确定性模板：

```text
用户描述
+ 8 个固定场景之一
+ 商品身份、比例、材质、颜色一致性约束
+ 禁止文字、水印、无关 Logo 和重复商品
```

8 个方向：

- `studio`
- `lifestyle`
- `detail`
- `seasonal`
- `editorial`
- `flat_lay`
- `outdoor`
- `gift`

超过 8 张时场景循环。API 传入 `prompts` 时直接使用自定义提示词。

### 8.2 模型请求

```http
POST {baseUrl}/images/generations
Authorization: Bearer {apiKey}
Content-Type: application/json
```

```json
{
  "model": "gpt-image-1",
  "prompt": "...",
  "n": 1,
  "size": "1024x1024",
  "quality": "high"
}
```

响应支持：

- `data[0].b64_json`
- `data[0].url`

每张图片单独请求。超时 180 秒。

### 8.3 演示模型

`mock` 根据 Prompt 哈希生成固定色彩和几何占位图。用于队列、Canvas、归档和 UI 验收，不代表真实商品效果。

## 9. Muse 自动化

### 9.1 指令

`content.js` 捕获 Enter 和表单 submit，只处理 `/vf` 开头文本。普通 Muse 消息不拦截。

### 9.2 DOM 查找

- 输入框：可见且可编辑的 `textarea`、`contenteditable`、`role=textbox`。
- 附件：表单内或页面最后一个图片 file 输入。
- 发送：`data-testid`、`aria-label`、`title`、中文“发送”或 submit。
- 结果图：Muse attachment presentation 或 generated-image 容器。

### 9.3 防串图

提交前记录已有图片 DOM 集合，提交后只取新增图片：

- 单图等待 4 分钟。
- 批量等待 5 分钟。
- 批量图片 URL 必须稳定 1.8 秒。
- 返回数量必须等于参考图数。
- 不满足时不映射，抛出错误并自动降级。
- `Delivery not confirmed` 立即结束当前等待。

## 10. 印花 ZIP 编排

1. 过滤非图片和单张大于 24MB 的文件。
2. 按 `webkitRelativePath` 排序。
3. 截取前 200 张。
4. 每批达到 4 张或原始大小接近 24MB 时切组。
5. `zip-builder.js` 生成 ZIP。
6. 压缩后超过 25MB 时二分继续拆分。
7. 单文件 ZIP 仍超限则跳过。
8. 点击开始调用目录 Handle 预留唯一顶层目录。
9. 每个内部批次使用同一 `archive_group_name`。

## 11. 归档

### 11.1 目录命名

```text
模块名[_货号]_YYYY-MM-DD_HH-mm-ss
```

普通任务在首次归档时创建唯一目录。印花任务开始时先预留唯一目录，保证多批次共享同一根。

### 11.2 普通任务

文件：

- 源图。
- 生成图片。
- 对比图。
- `manifest.json`。
- `manifest.csv`。
- `README.txt`。

### 11.3 印花任务

```text
根目录/
├─ 生成图/
└─ 拼图与清单/
```

生成图与清单位于同级目录。批次图片和清单均带 `批次NN_`。

### 11.4 写入安全

- 只使用用户授权根 Handle。
- 子目录和文件名经清洗。
- 不通过网页传入任意绝对路径。
- 不删除授权目录中的既有文件；同名文件重写前由任务目录隔离。

## 12. 扩展消息

| 消息 | 用途 |
| --- | --- |
| `VF_COMMAND_FROM_MUSE` | 内容脚本把 `/vf` 指令发给扩展 |
| `VF_PANEL_COMMAND` | background 通知挂件执行指令 |
| `VF_TAKE_PENDING_COMMAND` | 挂件读取暂存指令 |
| `VF_CLEAR_PENDING_COMMAND` | 清除暂存指令 |
| `VF_FETCH_IMAGE` | 后台下载 Muse CDN 图片 |
| `VF_HEALTH` | 兼容的健康/模型状态查询 |
| `VF_GET_DEFAULTS` | 读取模型配置 |
| `VF_SAVE_MODEL_SETTINGS` | 旧兼容入口，正式 UI 直接写 storage |

任务 CRUD、暂停和归档不再经过 background 或本机 API，而是在挂件内直接执行。

## 13. 错误处理

| 错误 | 处理 |
| --- | --- |
| 目录未选择 | 阻止任务，提示选择目录 |
| 目录权限失效 | 保存结果，任务卡提供重新授权 |
| 模型域名未授权 | 设置页阻止保存远程配置 |
| 模型请求失败 | 任务失败，错误写入任务记录 |
| Muse 投递失败 | 当前色/参考图失败，可局部重试 |
| 批量返回数量异常 | 不映射，自动改为逐张 |
| 所有 Logo 失败 | 任务失败 |
| 商品遮罩覆盖不足 | 提示提供遮罩 |
| 浏览器重载 | 进行中任务标记中断 |

## 15. 运维

### 15.1 更新扩展

1. 替换 `extension` 目录中的文件。
2. 在 `chrome://extensions` 点击扩展“重新加载”。
3. 刷新 Muse 页面。
4. 进入目录授权页重新授权。
5. 必要时重新保存模型配置。

### 15.2 定位问题

- 挂件状态显示“配置错误”：检查模型设置或 storage。
- 目录显示“尚未选择”：进入授权页选择。
- 目录显示“需要重新授权”：打开授权页确认。
- Muse DOM 错误：刷新页面，确认已登录。
- 任务历史消失：确认没有切换浏览器 Profile 或卸载扩展。
- 归档失败：检查目录是否被移动、删除或权限被撤销。

## 16. 安全与已知风险

- API Key 存于 `chrome.storage.local`，不属于安全密钥库。
- 可选 host permission 允许扩展访问用户授权的模型域名。
- 扩展不自动登录 Muse，不读取普通对话。
- Muse 图片下载只允许指定 CDN。
- 用户授权目录之外不执行写入。
- MV3 后台和挂件都可能被浏览器生命周期终止。
- 大图逐像素处理依赖浏览器内存；超大素材应分批。

## 17. 已停用的本地架构

`../backend/` 中的 Python 服务曾负责：

- HTTP API。
- SQLite 队列。
- Pillow 图像处理。
- Python 模型 provider。
- 桌面归档。

从扩展 `0.4.0` 起，这些能力在扩展内重新实现。保留 Python 项目不会影响扩展运行，但不再是必需的。
