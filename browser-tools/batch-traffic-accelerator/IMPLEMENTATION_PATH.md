# 指定规格流量加速：实现说明

## 当前交付

`v0.6.17` 已接入真实 TEMU 页面执行链路和持久化任务队列。侧边栏按“商品 → 地区查询 → 同地区全部站点”执行，每个任务独立保存参数、站点价格和商品缓存快照。

v0.6.11 在 v0.6.10 的同级商品来源基础上修复了三个现场问题：

1. 旧 `SKC导入` 中 11 位 SPU 被当作 SKC，执行时查询字段为空并报“缺少 SPU ID”。
2. 页面重载后没有恢复 `cacheMeta.source`，导致已有 43 个导入商品却仍显示“尚未载入商品”。
3. 迁移后缺少清晰汇总，用户无法从日志确认恢复了多少 SPU/SKC 和执行项。

当前修复会保留任务和队列暂停状态，不自动提交；迁移汇总写入全局日志、队列日志和任务执行日志。

### v0.6.12 页面脚本自恢复

现场启动 338 个 SKC × 19 个欧洲站点时，队列在第一个商品前暂停并记录：

```text
Could not establish connection. Receiving end does not exist.
```

根因是扩展原地重载后，已打开的 TEMU 标签页仍保留旧隔离世界，新版本无法向旧 content script 发送消息。v0.6.12 统一封装 `sendTabMessage`：识别该错误后自动执行 `chrome.scripting.executeScript` 注入 `content/content.js`，等待 300ms 并重试一次。恢复成功后继续当前商品，并在执行日志记录恢复事件；注入失败才暂停队列。

同一现场还发现店铺绑定值带有动态关注数，而流量分析页只返回主名称，旧归一化逻辑因此误判为不同店铺。v0.6.12 会移除末尾动态关注数后再比较，店铺主名称仍保持严格匹配。

### v0.6.13 商品 ID 类型选择器兼容

继续队列后，真实页面默认类型显示为 `SKU`，而旧代码只接受 `SPU/SKC`，导致首个 SKC 的 19 个站点全部报“没有找到商品 ID 类型选择框”。现场检查确认同一控件展开后包含 `SPU / SKC / SKU` 三个选项。

v0.6.13 把 `SKU` 纳入类型控件识别范围，并在切换后重新查找控件确认。Schema 17 会把该错误产生且未提交的异常项恢复为待处理，队列保持暂停。

### v0.6.14 系统性异常熔断

同一商品至少 3 个站点全部未提交，且错误文本完全一致时，执行器会判定为系统性异常，自动暂停队列，并把当前商品未提交站点恢复为待处理。正常“没有获取加速资格”“未找到站点商品行”不会触发熔断。

该保护用于防止页面级选择器变化或脚本异常导致后续 300 多个商品持续产生同类误判。

### v0.6.15 性能与单实例优化

本次优化包含：

1. 后台执行租约，单个页面独占执行；
2. 非执行页面可通过后台请求全局暂停；
3. 持久化时省略可重建的待处理项；
4. 热路径 500ms 合并保存，关键状态立即保存；
5. 只渲染当前步骤；
6. 执行时间线限制为最近 80 项；
7. 持久化日志分任务、队列截断。

压力测试数据：

```text
执行项：3800
时间线 DOM：80
页面 DOM：约 1615
持久化状态：约 0.07 MB
```

大规模实际队列复测：

```text
DOM：40505 → 2454
持久化：2.37 MB → 0.41 MB
存储执行项：6422 → 494（仅已变化项）
页面重载后：完整重建 6422 项
时间线 DOM：80
```

### v0.6.16 确认流程与速度优化

1. “确认”“取消”按钮只在当前价格弹窗内部查找；
2. 价格弹窗关闭改为检查可见规格行是否消失；
3. 确认后最多等待 10 秒，真实弹窗关闭后立即继续；
4. 商品间隔从 10 秒开始自适应，正常时最低降至 8 秒；
5. 请求频繁时恢复到用户配置上限；
6. SKC-only 任务暂不启用多 SKC 批量查询，因为结果行只显示 SPU。

### 当前开放问题

现场队列存在 `继续让价确认加载超时`、`流量加速弹窗加载超时` 和 `平台提示成功，但未确认站点进入流量加速中`。由于包含可能已提交的站点，未在本版本自动重试，留待单独排查。

插件资源：

```text

```

侧边栏通过下载链接提供：

```text
指定规格流量加速_标准导入模板.xlsx
```

模板内容：

| 工作表 | 内容 |
| --- | --- |
| `商品ID导入` | 1000 行，列：货号、SPU ID、SKC ID、启用、备注 |
| `国家价格` | 59 个站点，列：国家代码、国家名称、分组、启用、其他规格价格、指定规格价格、档位匹配价格、提交方式、备注 |

两个工作表的启用列都有“是/否”下拉选项。`SPU ID`、`SKC ID` 使用文本格式，价格列使用人民币数值格式。所有站点默认未启用，价格默认为空。

商品获取方式分为：

```text
商品列表检索 -> 扫描 goods/list
表格导入商品 ID -> 读取商品ID导入，不扫描商品列表
```

旧 `SKC导入` 工作表继续兼容：12 位 ID 按 SKC，11 位及以下按 SPU。

商品 ID 导入会写入独立日志：

```text
文件名
SPU ID 数量
SKC ID 数量
去重后的商品数量
无效或未启用数量
```

执行时每个商品还会记录：

```text
商品获取方式
ID 类型
具体 SPU/SKC ID
地区
站点数量
```

导入时，站点满足以下任一条件即启用：

```text
启用列填写“是”
或指定规格价格已填写
或档位匹配价格已填写
```

仅填写其他规格价格、但指定规格价格为空且启用列为空的站点保持停用。这样不会因为其他规格的公共兜底价格而把全部站点启用。

## 店铺绑定

内容脚本从 TEMU 页头读取当前店铺：

```text
[class*="account-info_mallInfo"]
[class*="account-info_accountInfo"]
```

用户点击“绑定店铺”后保存：

```text
店铺名称
域名
区域
绑定时间
```

任务创建时复制同一店铺快照。执行前同时校验：

```text
页面当前店铺 == 插件绑定店铺 == 任务绑定店铺
```

不一致时任务暂停，并记录“店铺不匹配”。插件不会自动删除其他店铺的任务，也不会自动把旧价格套到新店铺。

队列中的每个任务保存独立快照：

```text
任务配置
+ 站点价格
+ SPU/SKC 缓存
+ 加速时效和商品间隔
```

执行层级：

```text
Task 1
  Product 1
    EU 查询一次
      → 德国站
      → 法国站
      → 其他欧盟启用站点
  Product 2
    EU 查询一次
      → 德国站
      → 法国站
Task 2
  ...
```

同一商品、同一地区只查询一次。任务执行位置、任务状态和失败项持久化到 `chrome.storage.local`。暂停在当前“商品-地区”组完成后生效；浏览器重开后运行中任务恢复为暂停，由用户确认后继续。

队列支持：

- 独立添加任务；
- 编辑排队任务；
- 删除排队任务；
- 删除暂停任务；
- 拖动调整顺序；
- 清理已完成任务；
- 清除浏览器后恢复；
- 当前任务失败重试。

删除当前暂停任务会递增运行令牌、清除操作锁、当前任务 ID 和当前索引，然后重新计算队列状态。若队列仍有后续任务，执行指针会移到下一个未完成任务。

默认任务间隔：

```text
基础间隔：15 秒
随机抖动：0～3 秒
```

间隔可在侧边栏修改，界面最小值为 8 秒。检测到请求频繁时不会继续扩大请求量，队列会自动进入暂停，失败项保留为可重试状态。

## 单项真实链路

### 0. 商品池准备

任务支持两种检索方式：

```text
SKU 模糊查询
单类目检索
```

单类目任务通过平台“商品分类”级联框逐层选择，类目完整路径使用 `>` 分隔。类目任务里的货号 X 和规格 Y 都是可选二级过滤。

平台区域枚举为欧洲区、美国区、全球区。任务只执行与所选区域匹配的启用站点。

### 1. 切换地区

侧边栏根据站点分组推导地区：

```text
eu     -> https://agentseller-eu.temu.com/main/flux-analysis
us     -> https://agentseller-us.temu.com/main/flux-analysis
global -> https://agentseller.temu.com/main/flux-analysis
```

地区不一致时直接更新当前 TEMU 标签页，随后最多等待 15 秒，直到内容脚本确认页面类型为 `traffic`。

### 2. 查询商品

内容脚本：

1. 将商品 ID 类型切换为 `SPU` 或 `SKC`。
2. 在“多个查询请空格或逗号依次输入”输入目标 ID。
3. 点击“查询”。
4. 等待目标 ID 出现在结果中，或出现暂无数据。

### 3. 定位站点

遍历流量分析表格行，按以下组合精确定位：

```text
目标 SPU/SKC
+ 经营站点：目标站点
+ 商品行包含“首次加入站点日期”
```

当前页没有目标站点时，最多翻 30 页继续查找。

### 4. 资格判断

| 页面状态 | 结果 |
| --- | --- |
| 行内有“立即开启” | 继续执行 |
| 行内显示加速中或查看效果 | 成功，不重复加速 |
| 找到站点行但没有立即开启 | 异常：没有获取加速资格 |
| 找不到站点商品行 | 异常：没有获取加速资格 |

### 5. 开启弹窗

点击“立即开启”后等待“流量加速器”：

```text
第 1 次：最多等待 4.5 秒
未出现：等待 1.2 秒
第 2 次：重新定位目标行并点击，最多等待 7 秒
仍未出现：异常结束，不无限等待
```

### 6. 加速时效

默认选择“持续30天”。也可配置：

```text
长期持续加速
持续30天
持续14天
持续7天
```

插件读取平台 radio 的 `data-checked`，确认目标项已选中。

### 7. 去获取与填价

点击“去获取”打开“调整申报价”。每行读取：

```text
SKC
SKU
日常申报价格
参考申报价格
```

目标规格判断：

```text
Y 为空：
  所有 SKU 都不匹配目标规格，统一使用其他规格价格

Y 有值：
  SKC 名称完全匹配 Y
  或 SKU 名称包含 Y
```

价格解析：

```ts
configured = matchesTarget ? targetPrice : otherPrice;
missingPrice = configured == null || !Number.isFinite(Number(configured));
price = missingPrice ? null : configured;
overLimit = price > currentSkuReferencePrice;
valid = !missingPrice && price > 0 && !overLimit;
```

重要修复：

```ts
Number(null) === 0
```

旧版曾把空价格转成 `0`。v0.6.4 明确要求所有必需价格由用户填写：空价格不再回退到参考申报价，而是阻断整个站点提交。

### 8. 申报价确认

所有规格行通过后：

1. 点击“调整申报价”的“确认”。
2. 等待申报价弹窗关闭。
3. 确认外层的自定义价格已经生效。

### 9. 立即加速和最终确认

```text
点击“立即加速”
  ↓
等待“确认选择?”说明弹窗
  ↓
点击最终“确认”
  ↓
等待平台返回“流量加速成功”
```

最终确认按钮被点击前，任务仍可标记为异常；按钮点击后才把结果视为已提交。

### 价格回读与结果核对

申报价填写完成后等待 700ms，逐 SKU 读取输入框实际值。

```text
目标规格行：读取值必须等于指定规格价格
其他规格行：读取值必须等于其他规格价格
```

确认申报价后重新打开“去获取”，再次按 SKU 名称读取平台已保存值。实测弹窗标题为 `日常申报价格（CNY）`，填写 `27.13 / 27.93` 后确认并重开，平台仍返回相同值。

价格回读不一致：

- 不点击“立即加速”；
- 返回配置异常；
- 保存 SKU、目标值和实际值差异。

最终确认后重新定位目标站点行。只有出现“流量加速中/查看效果”且没有“立即开启”时才记成功；否则记录“已提交但结果不明”。

## 自动档位匹配

自动档位模式与指定规格价格模式共用商品查询、站点资格判断和加速时效选择，之后分叉：

```text
指定规格价格：
  去获取 → 调整申报价 → 逐 SKU 填价 → 确认 → 立即加速

自动档位：
  读取档位 → 计算候选 → 点击档位 → 立即加速
```

档位读取：

```text
div[class*="flux-shift-table_item__"]
排除 class 包含 beforeItem
读取 div[class*="rightCnt"] 中的人民币金额
选中态为 class 包含 itemActive
```

候选必须满足：

```text
目标价 <= 该档位每个 SKU 的对应申报价格
```

多个候选：

```text
优先更多流量 -> 平均对应申报价格最低
优先更少让价 -> 平均对应申报价格最高
```

没有候选时返回配置异常，例如：

```text
目标价 ¥150.00 高于所有档位的对应申报价格（最高 ¥144.99），没有满足条件的加速档位
```

只读预检消息为 `PREVIEW_ACCELERATION_TIERS`。它只读取和计算，不点击档位、不提交。

## 让价优先，档位兜底

执行顺序：

```text
检测“去获取”
  ↓
存在：打开调整申报价
      按目标规格价格和其他规格价格分别填写
      有效：确认申报价 → 立即加速 → 最终确认
  ↓
不存在、填价无效或无法继续：
      关闭调整申报价
      读取当前档位的 SKU 顺序和对应申报价
      每个 SKU 使用自己的目标规格价格或其他规格价格
      默认选择满足门槛的最高流量档
```

如果所有当前档位都不满足目标价格，按允许回退规则选择最高流量档，并在结果中标明：

```text
没有满足目标价格的档位，已按策略回退到现有最高流量档位
```

平台请求频繁、页面超时等临时失败不会触发价格档位回退，仍会暂停或进入可重试失败。
`PREVIEW_ACCELERATION_TIERS` 在第三种模式下返回：

- `continueDiscountAvailable`：是否检测到继续让价入口；
- `skuLabels`：SKU 顺序；
- `requiredPrices`：每个 SKU 使用的指定规格价或其他规格价；
- `usedFallback`：是否必须使用档位兜底。

## 解析占位价 `17/18` 清理

旧导入数据中，多个站点同时存在指定规格价格 `17` 或 `18`，启用列全部为“否”。根因是 Excel 将空单元格保存为 `<c .../>`，旧解析器吞并了后续“提交方式”单元格。

迁移规则：

```text
数值型目标价至少 3 个
且所有数值均等于 17 或 18
```

命中后：

1. 当前站点目标价置空；
2. 任务快照目标价置空；
3. 清除由这些目标价推导出的启用状态；
4. 导入诊断显示清理数量。

v0.6.3 的解析器将自闭合单元格作为独立空单元格处理，表格里的空白价格不再生成占位金额。迁移只在 schema 升级时执行，用于清理旧版本已经保存的错误数据。

## 异常与失败

分类依据是“是否需要修改业务配置”：

| 状态 | 边界 | 示例 |
| --- | --- | --- |
| `exception` | 配置或商品资格问题 | 没有资格、价格超限、找不到目标站点商品行 |
| `failed` | 临时请求或提交问题 | 请求频繁、网络中断、超时、页面未响应、已提交但结果不明 |

请求频繁、超时和页面未响应归入可重试失败。平台已提交但结果不明也归入失败，重试前应先核对平台。

## 重试规则

- 成功：不重试。
- 配置异常：不自动重试，避免无资格或价格超限形成循环。
- 可重试失败：点击“重试失败”后重新执行同一站点和商品。
- 重试前应先到平台核对，避免平台已成功但页面通信曾中断造成重复操作。

## 运行状态

```text
pending -> running -> success
                    -> exception
                    -> failed
```

任务：

```text
running <-> paused -> done
```

日志记录批量开始、每项开始、成功、异常、失败、暂停、继续、重试和批次汇总。任务结果可导出 CSV。

商品定位日志：

```text
商品定位检索：已载入 N 组候选 SPU/SKC
商品定位检索并查询流量资格
```

商品目录扫描负责建立候选集，实际执行时仍会逐 ID 在流量分析重新查询并按经营站点定位，不会直接复用商品列表页面行。

扫描时会自动把商品列表每页数量切换到 200，减少翻页次数。扫描锁存在时，“生成检查”“开始执行”和手动检索按钮不会启动第二个并发扫描。

缓存会保存扫描时的 `skuKeyword` 和 `specName`。参数修改后，旧缓存会显示为“参数已修改，当前为旧缓存”，开始执行和重试会被阻止，直到重新检索。若商品列表页存在“确认提交本页/放弃调整价格”遮罩，扫描会明确拒绝并提示新开正常商品列表标签页。

自动刷新流程：

```text
检测到缓存过期
→ 查询所有 goods/list 标签页
→ 当前活动页优先
→ 依次尝试正常商品列表，跳过遮罩页
→ 无可用页时新开商品列表
→ 执行 SKU 模糊查询、规格筛选和分页缓存
→ 成功后继续生成检查或真实执行
```

## 环境导出和导入

“导出环境配置”生成 JSON，包含：

- 店铺绑定；
- 参数；
- 站点价格；
- SPU/SKC 缓存；
- 任务队列和日志；
- 导入诊断。

不包含登录 Cookie、代理、浏览器指纹和账号密码。

导入步骤：

```text
读取 JSON
  → 校验 format / formatVersion
  → 校验环境店铺 == 当前页面店铺
  → 用户确认覆盖
  → 运行中任务改为暂停
  → 写入 chrome.storage.local
```

店铺不一致时拒绝导入，避免把一个店铺的价格和任务载入另一个店铺。

## 商品扫描完整性监控

点击查询后不再使用固定 2.2 秒后立即抓取的逻辑。扫描器会持续检查：

```text
加载提示是否消失
SPU/SKC 行签名是否连续稳定
当前页行数是否达到平台总数要求
```

示例故障：

```text
平台分页区域：共有 136 条
页面仍在显示：正在获取商品数据，请勿关闭此页面
当前只读取：9 条
```

此时不会把 9 条写入缓存，而是继续等待；超时后返回：

```text
商品数据数量校验失败：平台显示 136 条，实际读取 9 条
```

完整扫描结束后还会再做一次总数校验：

```text
所有页面实际行数 == 平台结果总数
```

校验失败时旧缓存保留，生成检查、加入任务和执行都会被阻断。

如果商品表只渲染当前可见的少量行，扫描器会自动在表格内部虚拟滚动，分批累计 SPU/SKC。实测首屏 8 组、平台总数 143 条时，自动滚动可读取完整 143 组；滚动过程显示进度，结束后恢复原滚动位置。

### 商品规格筛选兼容

部分 TEMU 页面版本的查询区没有“请输入规格名称”输入框，只有商品 ID、站点、商品属性、货号、商品名称和商品分类。

```text
存在规格筛选框 -> 一并填写
不存在         -> 继续按货号和/或类目扫描
```

规格 Y 仍保存在任务中，并在流量分析的“调整申报价”和档位 SKU 匹配阶段使用。界面会提示“已扫描全部匹配商品，目标规格将在流量分析阶段处理”，不会因此反复新开商品列表。

### 7043 现场验证

```text
店铺：Men Style Stories
货号：A2
规格：Mixed color1
平台结果：136 个商品
修复后扫描：136/136

```

修复同时包含：

- 已有商品列表但扫描失败时不再自动新开页面。

## 幂等建议

真实平台的页面已经会识别“已在加速中”并返回成功且不重复提交。为了提高跨重启安全性，逻辑键仍建议使用：

```text
spu + skc + station + specName + targetPrice + otherPrice + duration
```

提交状态应写为：

```text
validated -> submitting -> submitted / failed
```

当前执行器已在最终确认前保存内存中的 `submitted` 边界。后续可把 `submitting` 状态持久化，增强浏览器崩溃后的恢复能力。

## 限流软校验

只执行流量分析查询，不点击“立即开启”，不填写和提交价格：

| 查询间隔 | 连续查询数 | 可见“请求频繁” |
| --- | --- | --- |
| 5 秒 | 8 | 否 |
| 3 秒 | 6 | 否 |
| 2 秒 | 3 | 否 |
| 1.5 秒 | 6 次重复循环 | 否 |

查询接口没有在测试中显现限流，但完整商品任务包含更多页面动作和服务端写入，因此正式默认值仍设为 15 秒商品间隔，并加入 0～3 秒随机抖动。
