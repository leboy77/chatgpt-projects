# Temu 商品首图采集器 PRD

## 1. 产品目标

在 Temu 商品列表页中，对用户勾选的商品执行三种采集任务：

1. 获取商品卡片当前展示的首图。
2. 打开商品的 Quick look，按色值获取每个色值的首图。
3. 打开商品的 Quick look，按色值获取每个色值下的全部轮播图。

所有结果在浏览器本地打包成一个 ZIP。ZIP 内使用模式和本地时间建立唯一根目录，避免不同批次混在一起。

## 2. 核心原则

- 不调用未公开的 Temu 商品接口。
- 不复制 Cookie、登录令牌或请求签名。
- 只读取页面已经渲染的 DOM 和图片 URL。
- 不向第三方服务器上传商品或图片数据。
- Quick look 不存在或无法打开时，降级为卡片首图并在结果中记录警告。
- 单个商品失败不阻断整批任务。

## 3. 采集模式

| 模式 | 操作 | 输出 |
| --- | --- | --- |
| 简单采集 | 直接读取商品卡片中的首图，不打开 Quick look | 每个商品 1 张图 |
| 多首图采集 | 打开 Quick look，逐色值切换并读取轮播第 1 张 | 每个商品每个色值 1 张图 |
| 完整采集 | 打开 Quick look，逐色值切换并读取该色值下的全部轮播缩略图 | 每个商品每个色值一个子文件夹 |

三种模式共用一个“采集商品标题”开关。开启时标题经过安全字符清洗和长度限制后写入文件名、完整采集目录和 `采集结果.json`，同时在 ZIP 根目录生成 `商品标题.txt` 保存商品 ID 与完整标题。关闭时仅使用商品 ID、色值和轮播序号。

若商品没有 Quick look：

- 简单采集正常使用卡片首图。
- 多首图采集回退到卡片首图，色值记为 `默认`。
- 完整采集回退到卡片首图，色值记为 `默认`，并在任务摘要中标注“未找到 Quick look”。

## 4. 输出结构

文件名使用本地时间，精确到分钟。ZIP 根目录名中的空格、斜杠和冒号会替换为安全字符，确保 Windows 可解压使用。

### 4.1 简单采集

```text
简单采集+2026-10-23_16-09-45.zip
└─ 简单采集+2026-10-23_16-09-45/
   ├─ 607569376602895_首图.jpg
   ├─ 607423347706194_首图.jpg
   └─ 采集结果.json
```

### 4.2 多首图采集

```text
多首图采集+2026-10-23_16-09-45.zip
└─ 多首图采集+2026-10-23_16-09-45/
   ├─ 607569376602895_Grey_首图.jpg
   ├─ 607569376602895_Navy-Color_首图.jpg
   ├─ 607569376602895_Black_首图.jpg
   ├─ 607569376602895_fern-green_首图.jpg
   └─ 采集结果.json
```

### 4.3 完整采集

```text
完整采集+2026-10-23_16-09-45.zip
└─ 完整采集+2026-10-23_16-09-45/
   ├─ 607569376602895_Mens-Cargo-Pants/
   │  ├─ Grey/
   │  │  ├─ 01.jpg
   │  │  ├─ 02.jpg
   │  │  └─ 03.jpg
   │  ├─ Navy-Color/
   │  │  ├─ 01.jpg
   │  │  └─ 02.jpg
   │  └─ Black/
   │     └─ 01.jpg
   └─ 采集结果.json
```

`采集结果.json` 记录模式、开始时间、商品 ID、商品标题、色值、源 URL、目标文件、成功/失败状态，方便复核与去重。

## 5. 页面交互

### 5.1 商品选择

- 在商品卡片左上角注入采集勾选按钮。
- 点击按钮在“采集”和“已选”之间切换。
- 页面滚动并加载新商品后自动补注入按钮。
- 浮动工具条显示可采集数量与已选数量。

### 5.2 浮动工具条

包含：

- 全选可采集
- 清空选择
- 模式选择：简单采集 / 多首图采集 / 完整采集
- 采集商品标题开关
- 保存目录选择：可直接写入用户授权的文件夹，未选择时使用浏览器默认下载目录
- 清理 Temu 缓存：清理 HTTP 缓存、Cache Storage 和 Service Worker，不清 Cookie
- 开始采集
- 继续采集 / 重试失败项 / 放弃任务
- 进度和错误摘要
- 最小化

采集进行中禁用重复启动。完成后恢复按钮，并保留错误信息供查看。

## 6. 异常处理

- Quick look 打开超时：关闭残留弹窗，回退卡片首图。
- 某色值切换超时：继续尝试读取当前轮播；仍无图则记录该色值失败。
- 图片下载失败：对原图和无损参数地址最多重试 2 次。
- 单项失败：继续后续商品和色值。
- ZIP 无任何图片：不生成空文件，界面显示失败原因。
- 用户切换页面或刷新：保存任务进度和已读取的 Quick look 数据，返回 Temu 页面后可继续。
- 用户点击停止：不再读取后续商品，并将当前已经获取的图片生成 ZIP 保存。
- 检测到登录页或安全验证页：暂停任务，不自动下载半成品；验证完成后可继续。
- 失败重试：主批次结束后自动重试失败商品一次；仍失败时保留失败队列，按钮切换为“重试失败项”。

## 7. 非功能要求

- 单次采集不应占满主线程；下载并发默认 5。
- 单张图片超时默认 20 秒。
- Quick look 打开/关闭使用串行操作，防止多个弹窗互相覆盖。
- 不使用 jQuery、Layer 等旧前端依赖。
- 不包含无用大型库。
- 图片下载和 ZIP 生成全部在本地完成。

## 8. 验收标准

1. 在窗口 #7433 的 `mall.html` 页面能识别商品卡片和 Quick look。
2. 简单采集生成的 ZIP 根目录包含模式名和采集时间。
3. 多首图采集对测试商品生成 4 个色值首图。
4. 完整采集对每个色值生成独立子文件夹，文件按轮播顺序编号。
5. Quick look 不存在的商品不会中断整批任务。
6. ZIP 可在 Windows 资源管理器中正常打开。
7. 页面刷新后不残留不可点击的遮罩或采集状态。

## 9. 当前范围外

- 图片裁切、排版、AI 抠图和首图设计。
- 自动上传到 Temu 卖家后台。
- 绕过登录、验证码、风控或访问限制。
- 云端任务队列、多设备同步。
