# Temu 商品首图采集器技术路线

## 1. 总体架构

```text
Temu 页面 DOM
  ├─ 商品卡片扫描器
  ├─ 选择状态管理
  └─ Quick look 状态机
          ├─ 色值枚举
          ├─ 色值切换
          └─ 轮播 URL 快照
                    ↓
              采集任务队列
                    ↓
          图片 fetch + 重试 + MIME 判断
                    ↓
                 JSZip
                    ↓
            浏览器本地 ZIP 下载
```

不引入后台业务服务。扩展采用 Manifest V3、原生 JavaScript 和 JSZip。

## 2. Manifest 设计

- 内容脚本仅注入 `www.temu.com` 和 Temu 商品相关域名。
- 需要 `storage` 保存用户上次选择的模式、标题开关和未完成任务。
- 需要 `unlimitedStorage`，避免大批量临时状态受限。
- `host_permissions` 包含 Temu 页面与 `*.kwcdn.com` 图片 CDN。
- `web_accessible_resources` 不开放通配符。
- 不使用远程脚本，不执行动态下载的 JS。

## 3. 商品发现

主锚点：

```css
[data-tooltip^="goodContainer-"]
```

商品 ID 解析优先级：

1. `data-tooltip` 去掉 `goodContainer-`。
2. 商品链接中的 `-g-数字.html`。
3. 商品链接查询参数中的 `goods_id`。

首图解析优先级：

1. `img.goods-img-external` 的 `currentSrc`。
2. HTTP(S) 形式的 `src`。
3. `data-src`。
4. 父节点 CSS `background-image`。

过滤 `data:image/gif` 等懒加载占位图。

## 4. Quick look 状态机

状态：

```text
IDLE
  -> OPENING
  -> READY
  -> SWITCHING_COLOR
  -> SNAPSHOTTING
  -> CLOSING
  -> IDLE
```

### 4.1 打开

在商品卡片内查找文本为 `Quick look` 或 `快速查看` 的最小可点击元素：

```js
const control = card.querySelectorAll("button,a,span,[role='button']");
```

滚动卡片到视口，触发点击，然后等待尺寸大于 400×300 的 `[role="dialog"]`。

### 4.2 定位色值

不使用易变的哈希 class，也不要求色值缩略图已经完成懒加载。扫描 Quick look 内的规格单选项：

```css
[role="radio"][data-spec-value-id]
```

对单选项按最近公共父容器分组，再根据商品图片、`Color/颜色` 标签和尺码名称排除尺码组。即使色值缩略图全部仍是占位图，也能通过 `aria-label` 和可见文本识别色值名称。

如果已出现 `Color/颜色` 区域但仍未识别到色值，关闭 Quick look 后重新打开一次；再次失败才按默认单色值保存，并写入明确警告。

点击色值后必须确认 `aria-checked=true`，且轮播 URL 签名发生变化。按钮标记为 disabled、文本提示售罄、点击后未选中，或切换前后轮播签名相同，均视为无效色值并跳过，禁止把上一色值的图片重复写入当前色值。

### 4.3 切换与等待

点击色值后满足以下任一条件再快照：

- 该色值的 `aria-checked` 变为 `true`。
- 轮播第一张图片 URL 发生变化。
- 超过等待上限，则记录警告并使用当前轮播。

### 4.4 读取轮播

锚点：

```css
[role="listbox"]
  [role="option"][aria-label="Goods image"]
```

只选择宽度较小的缩略图项，避免与主预览图重复。每个色值保存：

- `data-index`
- 图片 `currentSrc` / `src` / `data-src`
- 背景图 URL 作为兜底

去掉 `?imageView2/...` 查询参数，优先下载 CDN 原图；原图失败时再用页面缩略图 URL 重试。

## 5. 四种模式

### 简单采集

不操作 Quick look，直接使用卡片首图。图片名：

```text
{productId}_首图.{ext}
```

### 多首图采集

逐商品打开 Quick look，逐色值读取轮播第一项。图片名：

```text
{productId}_{color}_首图.{ext}
```

### 完整采集

逐商品打开 Quick look，逐色值读取全部缩略图。目录：

```text
{productId}_{shortTitle}/{color}/{index}.{ext}
```

轮播编号按页面 `data-index` 排序，并从 `01` 开始。

### 详情图采集

从商品卡片读取产品链接，将当前商品 ID 和主采集/重试阶段写入 `tecActiveJob` 后导航到详情页。详情页内容脚本恢复同一任务，读取完整标题和详情页色值，再导航到下一个商品；全部完成后在最后一个详情页生成 ZIP。

详情图定位优先选择商品主内容区域内带 `Goods image` 选项的顶层图库，其次选择页面最上方、包含多张商品 CDN 图片的图库容器。页头购物车、推荐商品卡片和评论区卡片不参与详情图集合。色值识别复用 Quick look 的分组与排除规则，点击后等待 `aria-checked` 和图片签名变化。

目录：

```text
图片/{productId}_{title}_详情图_{color}_{index}.{ext}
```

“仅每色值首图”默认关闭；关闭时保存该色值全部详情图，开启时每个色值只保存第一张。任务保存 `detailFirstOnly`、`detailPhase` 和当前商品 ID，防止跨页面导航和失败重试重复处理。

## 6. 下载与打包

- Quick look 交互串行执行。
- 图片下载并发默认 5。
- 每张图片使用 `AbortController`，超时 20 秒。
- 原图失败后最多重试 2 次，并尝试页面实际缩略图 URL。
- MIME 决定扩展名：JPEG、PNG、WebP、AVIF、GIF；未知类型尝试根据 URL 扩展名判断。
- JSZip 保存 Blob，不进行二次压缩或质量损失。
- 用户通过 File System Access API 选择保存目录后，ZIP 直接写入该目录；目录句柄存入站点 IndexedDB。
- 浏览器不支持或目录权限失效时，回退到默认下载目录。
- 开启“仅导出图片链接（TXT）”时跳过图片 fetch、JSZip 和 ZIP 保存，直接保存文本 Blob。
- ZIP 文件名包含模式、日期和时间。ZIP 内不重复创建同名根目录，解压工具会按 ZIP 文件名创建唯一的顶层文件夹：

```text
完整采集+2026-10-23_16-09-45.zip
└─ 完整采集+2026-10-23_16-09-45/
   ├─ 图片/
   └─ 商品标题.xlsx
```

ZIP 内只有 `图片/` 和 `商品标题.xlsx` 两个顶层项目。简单采集和多首图采集在图片文件夹内平铺；完整采集继续使用 `图片/{商品ID}_{标题}/{色值}/{序号}.ext` 分层；详情图采集直接平铺为 `图片/{商品ID}_{标题}_详情图_{色值}_{序号}.ext`，避免商品和色值子文件夹。文件名统一清洗 Windows 不允许的 `<>:"/\|?*` 和控制字符，并限制目录深度与标题长度。

商品标题是全局可选项，默认开启。标题从商品卡片或详情页 DOM 读取，并清理图片 alt 中常见的 `item picture` 前缀；关闭时不写入文件名和标题表。开启时会在 ZIP 顶层生成 `商品标题.xlsx`，使用与参考模板一致的单个 `Sheet1`：A 列为 `序号`，B 列为 `标题`，B 列宽度为 122.875，数据按采集顺序从 1 连续编号。工作簿由 JSZip 直接生成最小 OOXML 包，不引入额外 XLSX 运行库。

商品扫描阶段会识别 `.js-goods-list` 内的直接区块标题。标题为 `Top picks for you`、`Top picks`、`为你推荐`、`猜你喜欢` 等推荐区的整组商品会被排除；其他区域中带可见小尺寸 `AD` 标识的卡片也会被排除。扫描器会移除排除卡片上可能遗留的选择按钮，并在启动采集前重新扫描一次，避免旧页面选中状态或断点任务继续采集推荐/广告商品。

### 6.1 图片链接文档

链接模式复用 `buildAssets` 已经解析出的 `sourceUrl`，按采集顺序去重。下载前先创建图片预览筛选窗口，每个条目显示缩略图、序号和源链接，并支持删除、恢复、恢复全部、确认导出与取消导出。删除条目只影响最终 TXT，不修改采集到的原始 URL 集合。确认后每行只写：

```text
{sourceUrl}
```

文档使用 UTF-8，并通过 Windows 兼容的 `\r\n` 换行。相同 URL 只输出一次；文档不包含商品 ID 和标题。文件名为 `{模式}+{时间戳}.txt`，支持用户授权的保存目录；不生成 ZIP、图片目录或标题工作簿。取消筛选或关闭窗口会将任务保留为暂停状态，不生成文档。

批量行选择不依赖易变的商品行容器 class。扫描器读取所有可采集卡片的 `getBoundingClientRect()`，按 `top` 相差不超过 12px 且再按 `left` 排序归入同一视觉行；每排在最后一次扫描时只保留一个行级按钮，固定在当前最右侧可采集卡片右上角。点击时按该排商品 ID 集合批量写入或删除选择状态，随后重新扫描页面，确保响应虚拟列表和懒加载。

### 6.2 自动翻页、数量与重复链接

自动翻页在正式采集前运行 `paging` 阶段，任务保存 `pagingPage`、`pageLimit`、`targetProducts`、`pagingComplete`、`filterAds` 和产品队列。当前页算第 1 页；当前页无手动勾选时收集全部可采集商品，有勾选时第 1 页只收集勾选项，后续页收集全部可采集商品。

加载下一批时优先查找 `See more / 查看更多 / 加载更多`；没有加载按钮时滚动到底部等待卡片集合增加；仍未增加时查找 `rel=next`、下一页文字或 `page/pageNum/page_no` 参数。达到目标商品数或页数上限立即停止。页面跳转时将状态保存为 `paging`，回到 Temu 列表页后自动续跑。

图片链接成功写入 ZIP 或 TXT 后，将 `sourceUrl` 写入 `chrome.storage.local` 的 `tecCollectedImageUrls`，最多保留最近 100,000 条。后续任务在构建 assets 后过滤历史 URL 和本批次重复 URL。预览中删除的链接不写入历史，因此下次仍可采集。用户可在工具条清空记录。

图片模式和链接模式共用缩略图预览窗口。图片模式在下载前显示“采集后图片小图预览”，确认后继续 JSZip；链接模式在写 TXT 前显示预览筛选。删除、恢复和取消操作只影响当前输出。

## 6.3 暂停、续采与失败重试

- 任务元数据保存到 `chrome.storage.local`，包括商品队列、已完成商品、已读取图片数据、失败商品、详情图阶段和暂停原因。
- 检测到 `login.html`、`bgn_*.html` 等登录/验证页时，将运行中的任务标记为暂停；页面恢复后显示“继续采集”。
- 恢复任务时跳过已完成商品，只处理未完成和失败商品。
- 主批次结束后，对失败商品自动执行一次集中重试。
- 连续 3 个商品 Quick look 或详情页读取失败时暂停，不能直接打包半成品。
- 详情图采集跨页面时自动恢复；主批次失败商品在 `detailPhase=retry` 阶段集中重试一次。
- 用户主动点击停止仍会打包当前结果，同时保留任务状态用于后续继续。

## 7. 状态与日志

每次任务维护：

```js
{
  mode,
  detailFirstOnly,
  exportLinksOnly,
  autoPaging,
  pageLimit,
  targetProducts,
  filterAds,
  filterDuplicates,
  detailPhase,
  currentProductId,
  startedAt,
  productsTotal,
  productsCompleted,
  imageTotal,
  imageSucceeded,
  imageFailed,
  records[],
  warnings[]
}
```

界面和工具条日志显示运行摘要、失败项与警告；ZIP 只保留图片和标题表。

工具条使用 Pointer Events 实现拖拽，位置保存到 `chrome.storage.local` 的 `tecPanelPosition`。拖动和窗口尺寸变化时按视口边界重新约束，双击标题栏清除保存位置并回到底部右侧。

停止任务时，已经完成下载的图片会继续进入 ZIP。若停止发生在 Quick look 读取阶段，则只保存已经读取过的商品，不再扩展到其余已选商品。

## 7.1 缓存清理

内容脚本向扩展 Service Worker 发送清理请求。Service Worker 只删除当前 Temu origin 的：

- HTTP cache
- Cache Storage
- Service Worker

不删除 Cookie、账号、localStorage、IndexedDB 或桌面文件。

## 8. 测试计划

1. 使用窗口 #7433 当前 `mall.html` 页面验证 100 个卡片发现。
2. 选择测试商品 `607569376602895`。
3. 验证色值：`Grey`、`Navy Color`、`Black`、`fern green`。
4. 验证色值切换后首图 URL 更新。
5. 验证完整采集能读取每个色值的 5 张缩略图。
6. 验证生成 ZIP 的目录层级、文件顺序和 JSON 记录。
7. 人工验证一个无 Quick look 商品与一个临街/虚拟列表商品的降级行为。
8. 用两个合成详情页验证自动 A→B 导航、详情标题、全部色值图片和“仅每色值首图”分支。
9. 开启链接模式验证预览窗口、删除链接后不进入 TXT、文档仅包含 URL，且下载目录没有图片文件或 ZIP。
10. 模拟三批列表验证页数、目标商品数、AD 是/否、重复链接历史和图片/链接预览确认分支。

## 9. 后续扩展

首图设计可作为独立阶段接入：

1. 从采集结果读取原图。
2. 按平台当期规格创建 Canvas/OffscreenCanvas。
3. 完成裁切、留白、背景、文字与品牌元素合成。
4. 批量预览并导出 JPEG/WebP。

该阶段独立于采集层，避免把 DOM 抓取与图像设计耦合。
