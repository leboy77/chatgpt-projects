# Temu 商品首图采集器技术路线

## 1. 总体架构

```text
Temu 页面 DOM
  ├─ 商品卡片扫描器
  ├─ 选择状态管理
  └─ Quick look 状态机
          ├─ 色值枚举
          ├─ 色值切换
          └─ 轮播 URL 快照
                    ↓
              采集任务队列
                    ↓
          图片 fetch + 重试 + MIME 判断
                    ↓
                 JSZip
                    ↓
            浏览器本地 ZIP 下载
```

不引入后台业务服务。扩展采用 Manifest V3、原生 JavaScript 和 JSZip。

## 2. Manifest 设计

- 内容脚本仅注入 `www.temu.com` 和 Temu 商品相关域名。
- 需要 `storage` 保存用户上次选择的模式、标题开关和未完成任务。
- 需要 `unlimitedStorage`，避免大批量临时状态受限。
- `host_permissions` 包含 Temu 页面与 `*.kwcdn.com` 图片 CDN。
- `web_accessible_resources` 不开放通配符。
- 不使用远程脚本，不执行动态下载的 JS。

## 3. 商品发现

主锚点：

```css
[data-tooltip^="goodContainer-"]
```

商品 ID 解析优先级：

1. `data-tooltip` 去掉 `goodContainer-`。
2. 商品链接中的 `-g-数字.html`。
3. 商品链接查询参数中的 `goods_id`。

首图解析优先级：

1. `img.goods-img-external` 的 `currentSrc`。
2. HTTP(S) 形式的 `src`。
3. `data-src`。
4. 父节点 CSS `background-image`。

过滤 `data:image/gif` 等懒加载占位图。

## 4. Quick look 状态机

状态：

```text
IDLE
  -> OPENING
  -> READY
  -> SWITCHING_COLOR
  -> SNAPSHOTTING
  -> CLOSING
  -> IDLE
```

### 4.1 打开

在商品卡片内查找文本为 `Quick look` 或 `快速查看` 的最小可点击元素：

```js
const control = card.querySelectorAll("button,a,span,[role='button']");
```

滚动卡片到视口，触发点击，然后等待尺寸大于 400×300 的 `[role="dialog"]`。

### 4.2 定位色值

不使用易变的哈希 class，也不要求色值缩略图已经完成懒加载。扫描 Quick look 内的规格单选项：

```css
[role="radio"][data-spec-value-id]
```

对单选项按最近公共父容器分组，再根据商品图片、`Color/颜色` 标签和尺码名称排除尺码组。即使色值缩略图全部仍是占位图，也能通过 `aria-label` 和可见文本识别色值名称。

如果已出现 `Color/颜色` 区域但仍未识别到色值，关闭 Quick look 后重新打开一次；再次失败才按默认单色值保存，并写入明确警告。

点击色值后必须确认 `aria-checked=true`，且轮播 URL 签名发生变化。按钮标记为 disabled、文本提示售罄、点击后未选中，或切换前后轮播签名相同，均视为无效色值并跳过，禁止把上一色值的图片重复写入当前色值。

### 4.3 切换与等待

点击色值后满足以下任一条件再快照：

- 该色值的 `aria-checked` 变为 `true`。
- 轮播第一张图片 URL 发生变化。
- 超过等待上限，则记录警告并使用当前轮播。

### 4.4 读取轮播

锚点：

```css
[role="listbox"]
  [role="option"][aria-label="Goods image"]
```

只选择宽度较小的缩略图项，避免与主预览图重复。每个色值保存：

- `data-index`
- 图片 `currentSrc` / `src` / `data-src`
- 背景图 URL 作为兜底

去掉 `?imageView2/...` 查询参数，优先下载 CDN 原图；原图失败时再用页面缩略图 URL 重试。

## 5. 三种模式

### 简单采集

不操作 Quick look，直接使用卡片首图。图片名：

```text
{productId}_首图.{ext}
```

### 多首图采集

逐商品打开 Quick look，逐色值读取轮播第一项。图片名：

```text
{productId}_{color}_首图.{ext}
```

### 完整采集

逐商品打开 Quick look，逐色值读取全部缩略图。目录：

```text
{productId}_{shortTitle}/{color}/{index}.{ext}
```

轮播编号按页面 `data-index` 排序，并从 `01` 开始。

## 6. 下载与打包

- Quick look 交互串行执行。
- 图片下载并发默认 5。
- 每张图片使用 `AbortController`，超时 20 秒。
- 原图失败后最多重试 2 次，并尝试页面实际缩略图 URL。
- MIME 决定扩展名：JPEG、PNG、WebP、AVIF、GIF；未知类型尝试根据 URL 扩展名判断。
- JSZip 保存 Blob，不进行二次压缩或质量损失。
- 用户通过 File System Access API 选择保存目录后，ZIP 直接写入该目录；目录句柄存入站点 IndexedDB。
- 浏览器不支持或目录权限失效时，回退到默认下载目录。
- ZIP 根目录包含模式、日期和时间，例如：

```text
完整采集+2026-10-23_16-09-45/
```

文件名统一清洗 Windows 不允许的 `<>:"/\|?*` 和控制字符，并限制目录深度与标题长度。

商品标题是全局可选项，默认开启。标题只从当前商品卡片 DOM 读取，不额外请求详情页，并清理图片 alt 中常见的 `item picture` 前缀；关闭时不写入文件名、目录和 JSON。开启时还会在 ZIP 根目录生成 `商品标题.txt`，每行保存“商品 ID + 完整标题”，避免文件名截断导致标题不完整。

## 6.1 暂停、续采与失败重试

- 任务元数据保存到 `chrome.storage.local`，包括商品队列、已完成商品、已读取 Quick look 数据、失败商品和暂停原因。
- 检测到 `login.html`、`bgn_*.html` 等登录/验证页时，将运行中的任务标记为暂停；页面恢复后显示“继续采集”。
- 恢复任务时跳过已完成商品，只处理未完成和失败商品。
- 主批次结束后，对失败商品自动执行一次集中重试。
- 连续 3 个商品 Quick look 失败时暂停，不能直接打包半成品。
- 用户主动点击停止仍会打包当前结果，同时保留任务状态用于后续继续。

## 7. 状态与日志

每次任务维护：

```js
{
  mode,
  startedAt,
  productsTotal,
  productsCompleted,
  imageTotal,
  imageSucceeded,
  imageFailed,
  records[],
  warnings[]
}
```

界面只显示摘要，完整记录写入 ZIP 内 `采集结果.json`。

停止任务时，已经完成下载的图片会继续进入 ZIP。若停止发生在 Quick look 读取阶段，则只保存已经读取过的商品，不再扩展到其余已选商品。

## 7.1 缓存清理

内容脚本向扩展 Service Worker 发送清理请求。Service Worker 只删除当前 Temu origin 的：

- HTTP cache
- Cache Storage
- Service Worker

不删除 Cookie、账号、localStorage、IndexedDB 或桌面文件。

## 8. 测试计划

1. 使用窗口 #7433 当前 `mall.html` 页面验证 100 个卡片发现。
2. 选择测试商品 `607569376602895`。
3. 验证色值：`Grey`、`Navy Color`、`Black`、`fern green`。
4. 验证色值切换后首图 URL 更新。
5. 验证完整采集能读取每个色值的 5 张缩略图。
6. 验证生成 ZIP 的目录层级、文件顺序和 JSON 记录。
7. 人工验证一个无 Quick look 商品与一个临街/虚拟列表商品的降级行为。

## 9. 后续扩展

首图设计可作为独立阶段接入：

1. 从采集结果读取原图。
2. 按平台当期规格创建 Canvas/OffscreenCanvas。
3. 完成裁切、留白、背景、文字与品牌元素合成。
4. 批量预览并导出 JPEG/WebP。

该阶段独立于采集层，避免把 DOM 抓取与图像设计耦合。
