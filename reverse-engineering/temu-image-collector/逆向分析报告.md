# TEMU 产品列表图片下载 v1.1.0 逆向分析

## 结论摘要

这个扩展本质上是一个“页面 DOM 采集器”，不是 Temu 接口客户端，也不是首图设计器。

它的完整处理链路是：

1. 在 Temu 列表页轮询商品卡片。
2. 从卡片的 `data-tooltip` 中提取商品 ID。
3. 向每张卡片注入“选中/已选/已下”按钮。
4. 用户勾选后，从卡片中的 `img.goods-img-external` 读取图片 URL。
5. 使用页面上下文的 `fetch` 下载图片。
6. 使用 JSZip 在浏览器本地按商品 ID 命名并打包成 ZIP。

脚本中没有 Temu 商品详情 API、签名算法、Cookie/令牌读取、上传接口或远程业务后端。唯一的业务网络请求是下载已经从页面读取到的图片 URL。

代码中没有 Canvas、图片裁切、文字排版、合成、重新编码或上传逻辑。因此它不能“设计”首图，只能收集列表卡片当前展示的商品图片。所谓“首图”能力来自商品列表自身展示的图片，不是扩展生成的。

## 扩展组成

Manifest 只在 `document_end` 注入内容脚本，没有后台 Service Worker、弹窗页、原生消息或远程配置。

| 组件 | 用途 |
| --- | --- |
| jQuery 3.3.1 | DOM 查询和事件绑定 |
| Layer 3.1.1 | 提示框、确认框、进度文本区 |
| JSZip 3.10.1 | 在浏览器内生成 ZIP |
| `lib/jclps.js` | 商品发现、选中状态、图片下载和 ZIP 组织 |
| `lib/xlsx.full.min.js` | 未被 Manifest 加载，也未被主脚本引用 |

`xlsx.full.min.js` 约 936 KB，占扩展总体积约 73%，是无效负载。它既不会出现在页面中，也不参与下载流程。

Manifest 的 `web_accessible_resources` 允许所有站点访问扩展内的全部资源：

```json
"web_accessible_resources": [
  {
    "resources": ["*"],
    "matches": ["<all_urls>"]
  }
]
```

实际只需要把 `lib/jclps.js` 暴露给 `www.temu.com`，当前配置属于明显的过度授权。

## 运行模型

脚本使用 `chrome.extension` 判断自己运行在扩展内容脚本环境还是普通页面环境，形成一套“双执行环境”结构。

### 内容脚本环境

它通过 `chrome.runtime.getURL("lib/jclps.js")` 取得扩展 URL，再动态插入：

```html
<script src="chrome-extension://.../lib/jclps.js"></script>
```

随后在页面右侧创建固定工具条：

- 全选
- 更多
- 取消
- 下载
- 清空

这个执行环境负责 UI、选择状态、下载、打包以及 `chrome.storage.local` 读写。

### 页面执行环境

第二次执行时检测不到内容脚本专用的 `chrome.extension`，进入页面侧分支。页面侧负责扫描商品卡片，并向卡片实际 DOM 中注入“选中”按钮。

两个环境通过共享 DOM 协作，不通过消息接口通信。这是该扩展最重要的架构特征。

## 商品发现逻辑

脚本每约 700 ms 扫描一次未处理的商品卡片。

搜索页选择器：

```css
.js-search-goodsList
  [data-tooltip^="goodContainer-"]:not([oapewe="1"])
```

品类/列表页选择器：

```css
.js-goods-list
  [data-tooltip^="goodContainer-"]:not([oapewe="1"])
```

品类页还要求商品列表位于：

```text
#mall-top-head-category-container
  -> nextElementSibling[classList contains "mainContent"]
```

找到卡片后：

1. 写入自定义哨兵属性 `oapewe="1"`，避免重复注入。
2. 读取 `data-tooltip`。
3. 去掉前缀 `goodContainer-`，把剩余部分作为商品 ID。
4. 创建按钮 `.piacewcewvs`。
5. 将商品 ID 写入按钮的 `data-aipe`。

商品 ID 来源等价于：

```js
const productId = card
  .getAttribute("data-tooltip")
  .replace("goodContainer-", "");
```

它没有读取商品链接中的 `goods_id`，也没有进入商品详情页。

## 自定义状态属性

脚本大量使用非标准属性保存状态：

| 属性 | 含义 |
| --- | --- |
| `oapewe="1"` | 该商品卡片已注入按钮 |
| `poae="1"` | 该按钮已经初始化过 |
| `bwwvoae="0"` | 当前不是已完成下载状态 |
| `bwwvoae="1"` | 当前已下载，通常显示“已下” |
| `seece="0/1"` | 右键整行选择操作的临时状态 |
| `data-aipe` | 商品 ID |

按钮文本同时参与业务状态判断：

- `选中`：未选择
- `已选`：等待下载
- `已下`：下载完成

这种设计依赖文字和属性保持一致。任意一处被 Temu 页面重绘或脚本异常打断，状态就会失真。

## 点击选择与“更多”

初始化后约每 1 秒检查按钮：

- 若有 `chrome.storage.local[商品ID]`，显示“已下”并标绿。
- 否则绑定点击事件，在“选中”和“已选”之间切换。

“更多”按钮不会请求分页 API，而是模拟用户行为：

1. 查找包含 `查看更多` 的 `span`。
2. 滚动到该按钮附近。
3. 直接调用 `span.click()`。
4. 每约 500 ms 检查新商品，最多等待 6 次。
5. 新卡片出现后继续注入选择按钮。

因此它受 Temu 的懒加载、虚拟列表、登录状态、页面结构和限流策略影响。文件时间为 2025 年，选择器对 2026 年的 Temu 页面可能已经失效。

## 图片提取逻辑

点击“下载”时，脚本遍历：

```css
.piacewcewvs[bwwvoae="0"]
```

并只处理文本为“已选”的按钮。

图片查询范围是按钮的直接父节点：

```css
img.goods-img-external,
.goods-img-external img
```

取值逻辑等价于：

```js
const imageElement = button
  .parent()
  .find("img.goods-img-external,.goods-img-external img")[0];

const imageUrl = (
  imageElement.src ||
  imageElement.getAttribute("data-src")
).split("?")[0];
```

这有两个直接局限：

1. 只能得到列表卡片当前主缩略图，不能批量得到商品详情轮播图。
2. 优先使用 `src`。如果懒加载时 `src` 是占位图而真实地址在 `data-src`，脚本会把占位图当成真图。

URL 末尾执行 `.split("?")[0]`，去掉全部查询参数。它可能因此获得 CDN 原图，也可能破坏依赖查询参数的图片地址；脚本没有兜底重试。

之后按商品 ID 去重：

```js
const result = [];
const seen = new Set();
for (const item of items) {
  if (!seen.has(item.name)) {
    seen.add(item.name);
    result.push(item);
  }
}
```

同一商品 ID 只保留第一项。

## 下载与 ZIP 实现

下载参数：

| 参数 | 值 |
| --- | --- |
| 并发数 | 20 |
| 非首项延迟 | 300 ms |
| 单张超时 | 15 秒 |
| 输出形式 | `Blob` + JSZip |
| ZIP 文件名 | `YYYY-MM-DD HH-mm-ss图片包.zip` |
| 图片文件名 | `商品ID.扩展名` |

单张图片的处理流程：

```js
const response = await fetch(url, {
  signal: abortController.signal,
});

const blob = await response.blob();
zip.file(`${productId}.${extension}`, blob);
```

扩展名来自响应的 `Content-Type`：

- `image/jpeg` 转为 `jpg`
- 其他类型取斜杠后的子类型，例如 `png`、`webp`
- 没有 `Content-Type` 时默认 `image/jpeg`

图片不会重新压缩或裁切，ZIP 中保存的是响应返回的原始二进制。

最终使用 JSZip 生成 Blob，再通过临时的 `<a download>` 触发浏览器下载：

```js
const zipBlob = await zip.generateAsync({ type: "blob" });
const link = document.createElement("a");
link.href = URL.createObjectURL(zipBlob);
link.download = zipName;
link.click();
```

因为使用 `<a download>`，Manifest 不需要 `downloads` 权限。

## 实际网络行为

业务网络调用只有一处：

```js
fetch(imageUrl, { signal });
```

`imageUrl` 直接来自当前页面的商品图片 DOM。

没有发现：

- 固定 Temu API 路径
- `XMLHttpRequest`
- `FormData`
- 商品 Cookie 或 Authorization 读取
- 请求签名、加密参数或风控 Token 生成
- 远程服务器上报、上传或配置下载
- 原生消息
- IndexedDB

所以它没有“破解 Temu 接口”，而是把浏览器已经渲染出来的图片地址再拉取一次。

图片 CDN 如果不是同源，`fetch` 的成功与否取决于 CDN 的 CORS 响应头。扩展没有 `host_permissions`，也没有 CORS 失败后的替代下载方式，因此 CDN 一旦收紧跨域策略，整个下载流程就会失败。

## 存储逻辑

扩展使用 `chrome.storage.local` 保存成功下载过的商品 ID，数据库中只出现以下 API：

```js
chrome.storage.local.get(...)
chrome.storage.local.set(...)
chrome.storage.local.clear(...)
```

“清空”按钮调用的是整个扩展存储空间的 `clear()`，而不是删除已知商品 ID 对应的键。

## 已发现的实现缺陷

### 1. 依赖文本而不是纯状态属性

下载判断同时依赖 `bwwvoae` 和按钮文本“已选”。样式只是视觉反馈，文本却被用作业务数据，容易被页面重绘、语言切换或其他脚本破坏。

### 2. 缩略图懒加载兼容性差

代码先取 `src`，再取 `data-src`。常见的 `src="data:image/gif;base64,..."` 懒加载占位图会优先命中，造成下载到占位图或错误格式。

### 3. 选择器高度依赖 Temu DOM

`data-tooltip="goodContainer-..."`、`.js-goods-list`、`.js-search-goodsList`、`.goods-img-external` 都是内部实现细节，Temu 改版即可导致失效。

### 4. 并发过高

20 个并发下载很可能触发 CDN 限流。300 ms 延迟是每个工作协程的起跑延迟，不是全局节流，实际会出现一批近同时请求。

### 5. 无失败重试

下载失败只记录错误文本，不重试、不指数退避、不区分 CORS、404、429 和超时。

### 6. 不必要的依赖和过宽权限

未使用的 SheetJS 增加约 936 KB；`web_accessible_resources` 对所有站点开放全部文件，明显超过实际所需权限。

## 与“设计首图”的差距

当前代码没有以下任何能力：

- 画布创建或固定尺寸输出
- 商品主体抠图、裁切、留白
- 背景替换
- 标题、卖点和徽标排版
- 多商品模板合成
- 首图效果预览
- JPEG/WebP 质量控制
- 上传回 Temu 或卖家后台

如果目标是做“首图设计”工具，合理架构应分成两个独立部分：

1. **采集层**：从商品卡片的链接中稳定提取商品 ID，并获取最高可用分辨率的源图。
2. **设计层**：在 Canvas/OffscreenCanvas 中按平台当期规格裁切、合成、预览和批量导出。

采集层不应依赖按钮文本，也不应先取懒加载占位图；应优先检查 `currentSrc`、`srcset`、真实 `data-src`，并保留可用的 CDN 参数。

设计层可在本地完成，不必把商品图上传到第三方服务器。批量导出时可同时生成图片 ZIP 和 CSV/XLSX 清单，记录商品 ID、源图 URL、输出尺寸和处理状态。

## 总体评价

技术实现简单直接，核心是：

```text
DOM 轮询
  -> 商品卡片与商品 ID
  -> 卡片图片 URL
  -> fetch 二进制
  -> JSZip
  -> a[download]
```

优点是完全在浏览器本地执行，没有发现远程控制或隐蔽上传；缺点是强依赖页面结构、没有接口层、错误处理薄弱，并带有大量无效依赖和混淆死分支。
