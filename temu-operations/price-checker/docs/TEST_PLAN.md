# 测试计划

## 1. 目标

验证核价规则、SKC 导入、任务规划和幂等逻辑，并在接入真实 Temu 页面前建立可重复的自动化基线。

## 2. 测试层级

| 层级 | 环境 | 目的 |
| --- | --- | --- |
| 规则单元测试 | Node.js | 金额、比较、去重、规划、幂等 |
| 页面适配测试 | 本地模拟页 | 分页、筛选、全选、批量菜单、弹窗读取 |
| 扩展 E2E | Chromium + 本地模拟页 | 侧边栏到提交预览的完整流程 |
| 真实只读烟测 | 比特浏览器 + Temu | DOM 结构、字段、行数、稳定性 |
| 真实受控提交 | 比特浏览器 + Temu | 1 行、5 行、20 SKU、50 SKC 单批、1000 SKC 计算逐级放量 |

## 3. 必测边界

### SKC 导入

- 0、1、49、50、51、999、1000、1001 条。
- 1000 条必须形成 20 批，每批 50 条。
- 51 条必须形成 50 + 1 两批。
- Excel 以数字存储 SKC 时无科学计数法丢失。
- 空格、制表符、BOM、CSV 引号。
- 重复 ID。
- 混合货号。
- 禁用行和空行。

### 金额

- `0.01`、`0.10`、两位小数和超两位小数。
- 金额恰好等于边界。
- 浮点 `0.1 + 0.2` 不影响比较。
- 原币换算产生四舍五入。
- 汇率缺失、过期、为 0 或负数。

### 页面状态

- SPA 重新渲染导致旧节点失效。
- 站点与 SKU 平行加载。
- 空站点、部分 SKU 缺失价格。
- 打开弹窗后出现二次安全提示。
- 提交过程中网络断开。
- 提交后页面返回未知状态。

## 4. 真实账号放量顺序

1. 登录并确认当前店铺。
2. 只读：不勾选、不打开提交弹窗的页面准备测试。
3. 只读：打开确认弹窗并导出脱敏扫描结果。
4. 1 个 SKC / 1 个可提交 SKU，人工对照后提交。
5. 5 个 SKC，多站点但不超过 20 个 SKU。
6. 1000 个 SKC，按 20 批处理并核对提交结果。

任何阶段出现字段错位、金额不一致、重复弹窗或未知提交状态，立即停止放量。

## 5. 通过标准

- 单元测试全部通过。
- 模拟批量任务无重复提交。
- 平台价大于、等于申报价时直接接受，低于申报价时进入还价。
- 未知页面状态不会继续点击。
- 1000 SKC 任务可稳定拆成 20 批并完成扫描。
- 真实只读扫描结果经人工抽查 100% 一致。
