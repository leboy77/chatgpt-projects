# 文档维护规范

适用范围：TEMU 图片助手所有版本更新。

目标：PRD、技术设计、用户公告、版本记录和安装包始终对应当前代码，不再出现“代码已更新但文档停在旧版本”的情况。

---

## 1. 文档职责

| 文档 | 职责 | 是否当前版 |
| --- | --- | --- |
| [PRD.md](./PRD.md) | 产品定位、用户流程、功能需求、参数、异常规则、验收标准 | 是 |
| [技术设计.md](./技术设计.md) | 架构、数据模型、状态机、DOM 自动化、测试与限制 | 是 |
| [初次使用公告.md](./初次使用公告.md) | 面向使用者的安装、准备、执行、异常处理说明 | 是 |
| [CHANGELOG.md](./CHANGELOG.md) | 版本级变化摘要 | 是 |
| `extension/README.md` | 安装、使用、发布说明、文档入口 | 是 |
| `docs/archive/*` | 历史详细需求/技术方案/决策记录 | 否，只追加不改写 |

### 单一事实来源

- “产品应该怎样”以 **PRD.md** 为准。
- “代码现在怎样实现”以 **技术设计.md** 为准。
- “这个版本改了什么”以 **CHANGELOG.md** 为准。
- 历史根因和逐版本修复过程查 **archive**。

---

## 2. 更新类型与必改文档

| 变更类型 | PRD | 技术设计 | CHANGELOG | README / 使用公告 |
| --- | --- | --- | --- | --- |
| 修 Bug，行为不变 | 一般不改 | 实现/选择器变化则改 | 必改 | README 发布说明必改 |
| 修改现有行为 | 必改 | 必改 | 必改 | 使用方式变化则改 |
| 新增功能 | 必改 | 必改 | 必改 | 使用公告与 README 必改 |
| 新增/修改参数 | 参数表必改 | 配置/数据模型必改 | 必改 | 使用说明必改 |
| 只改 UI 外观 | UX 部分按需 | UI 实现必改 | 必改 | 截图/说明按需 |
| 只改平台选择器 | 一般不改 | 选择器表必改 | 必改 | 一般不改 |
| 只改测试/工具 | 一般不改 | 测试章节必改 | 可改 | 一般不改 |

## 3. 发版检查表

每个版本按顺序执行：

1. **版本号**
   - `extension/manifest.json` 的 `version`
   - `extension/page/main.js` 的 `VERSION`
   - 两者必须一致。
2. **CHANGELOG**
   - 在顶部增加 `## vX.Y.Z — YYYY-MM-DD`。
   - 写清新增、修复、验证。
3. **PRD**
   - 标题版本号更新。
   - 功能/参数/异常/验收标准按实际变化更新。
4. **技术设计**
   - 标题版本号更新。
   - 架构、数据模型、状态机、选择器、测试、已知限制按实际变化更新。
5. **使用公告与 README**
   - 使用方式变化必须同步。
   - README 的版本标题和发布说明必须更新。
6. **历史归档**
   - 不修改旧归档；如需新增历史快照，在 `docs/archive/` 增加带版本号的文件。
7. **自动校验与打包**

```powershell
python tools/build_release.py --check
python tools/build_release.py
```

`--check` 只校验文档同步；不带参数会校验并生成：

```text
release/TEMU图片助手v<version>.zip
release/TEMU图片助手v<version>-Markdown文档.zip
```

8. **真机验证**
   - 至少验证受影响的主流程。
   - 真实提交类功能优先使用安全演练。
   - 在 CHANGELOG/技术设计中记录验证商品或窗口。

## 4. 版本号规则

- `PATCH`：修 Bug、选择器修复、文案/小 UI 修复。
- `MINOR`：新增功能、参数、流程或页面能力。
- `MAJOR`：不兼容的数据结构或产品形态变化。

当前处于 `0.x`，默认：

- 小修复 → `0.10.16`
- 新功能 → `0.11.0`

---

## 5. 文档写作规则

- PRD 只写“现在要什么”，不把逐版本调试过程堆进去。
- 技术设计只写“现在怎么实现”，历史根因放 archive。
- 所有参数写默认值、范围、影响。
- 所有异常写触发条件、处理方式、是否会停止/重试。
- 所有页面写 URL、关键选择器、按钮文本。
- 提交类功能必须写清“安全演练”和“正常提交”的差异。
- 新增功能必须写验收标准。

---

## 6. 归档规则

- `docs/archive/` 只追加，不回写旧内容。
- 大版本或重大重构时，可复制当前 PRD/技术设计为带版本号的快照。
- 归档文件保留原始文件名时，内部相对链接继续有效。
- 当前版文档中的历史链接统一指向 `archive/`。

---

## 7. Definition of Done

一个版本只有在以下条件全部满足时才算完成：

- [ ] 版本号一致
- [ ] CHANGELOG 已更新
- [ ] PRD 已按需更新
- [ ] 技术设计已按需更新
- [ ] README / 使用公告已按需更新
- [ ] `python tools/build_release.py --check` 通过
- [ ] 安装包和 Markdown 文档包已生成
- [ ] 受影响的真机流程已验证
- [ ] 已知限制已记录
