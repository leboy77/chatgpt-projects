## 1. 架构总览

```text
TEMU 页面
  ├─ page/main.js（MAIN world）
  │    ├─ Shadow DOM 工作台
  │    ├─ 页面 DOM 自动化
  │    ├─ 任务状态机
  │    ├─ IndexedDB 持久化
  │    └─ Excel 解析/回写
  │
  ├─ content/bridge.js（ISOLATED world）
  │    └─ window.postMessage ↔ chrome.runtime.sendMessage
  │
  └─ background.js（Service Worker）
       ├─ 注册 MAIN world 注入脚本
       ├─ 截图 / 调整窗口
       ├─ 真实输入与真实点击（chrome.debugger）
       ├─ 受控导航
       ├─ 查找/关闭标签页
       └─ 返回 tabId/windowId
```

### 1.1 为什么使用 MAIN world

TEMU 页面使用 React 和自研 `beast-core` 组件。部分操作（DataTransfer、showDirectoryPicker、原生 input setter、原生事件）在 ISOLATED world 中受限，因此主逻辑注册到 `MAIN` world，直接操作页面上下文。

### 1.2 组件职责

| 文件 | 职责 |
| --- | --- |
| `extension/manifest.json` | MV3 清单、权限、版本、背景 Service Worker |
| `extension/background.js` | 注册注入脚本、截图、窗口、调试器输入/点击、导航、标签页查询 |
| `extension/content/bridge.js` | 兜底注入、页面与扩展消息转发 |
| `extension/page/main.js` | 全部 UI、任务状态、页面自动化、素材中心、Excel、轮播图维护 |
| `extension/icons/*` | 扩展图标 |

### 1.3 权限

```text
storage
scripting
activeTab
debugger
host_permissions: https://agentseller.temu.com/*
```

`debugger` 用于真实键盘输入/真实点击和受控导航。注意：部分比特浏览器窗口会拒绝调试器访问图片更新页，因此轮播图流程改用 `element.click()`。

## 2. 页面注入与消息通道

### 2.1 注入顺序

1. `background.js` 用 `chrome.scripting.registerContentScripts` 注册 `page/main.js` 到 MAIN world。
2. `content/bridge.js` 在 `document_start` 注入 ISOLATED world。
3. 若 3 秒后页面仍无 `#temu-image-bot-host`，bridge 用 `<script src=chrome-extension://.../page/main.js>` 兜底注入。
4. `main.js` 创建 Shadow DOM 工作台并执行 `boot()`。

### 2.2 消息类型

| 类型 | 方向 | 用途 |
| --- | --- | --- |
| `PING` | page → background | 版本/权限/标签页探测 |
| `CAPTURE_TAB` | page → background | 截图 |
| `ENSURE_WINDOW` | page → background | 放大窗口，避免弹窗按钮被裁 |
| `TYPE_TEXT` | page → background | 调试器真实键盘输入 |
| `REAL_CLICK` | page → background | 调试器真实鼠标点击 |
| `NAVIGATE_URL` | page → background | 受控导航，自动处理“离开此网站” |
| `FIND_CONFIRM_TAB` | page → background | 查找 `/newon/product-select*` 确认页 |
| `FIND_TAB` | page → background | 按 URL 关键字查找标签页；按 tabId 倒序取最新 |
| `GET_TAB_INFO` | page → background | 获取当前 tabId/windowId |
| `CLOSE_TAB` | page → background | 关闭重复标签页 |

`TYPE_TEXT`、`REAL_CLICK`、`NAVIGATE_URL` 会优先使用消息里显式传入的 `tabId`，避免调试器附加到错误标签页。

## 3. 数据模型与持久化

### 3.1 IndexedDB

```text
DB: temu-image-bot
Store: kv（键值对）
```

| Key | 内容 |
| --- | --- |
| `multiTasks` | 任务库数组；每个任务含 id、货号、状态、snapshot、时间 |
| `task` | 当前任务快照（兼容旧版） |
| `ui` | 主题、位置、尺寸、折叠/关闭、备注、当前任务 id |
| `task:<taskId>:frontFiles` | 主图 File[] |
| `task:<taskId>:backFiles` | 背面图 File[] |
| `task:<taskId>:frontDirName` | 主图目录名 |
| `task:<taskId>:backDirName` | 背面图目录名 |
| `task:<taskId>:xlsxParts` | 原 xlsx 的 OOXML 部件，供状态回写 |
| `imageTaskJob` | 轮播图维护批次状态 |
| `imageTaskFiles` | 轮播图维护新增图片 File[] |

### 3.2 商品任务状态

```text
status: draft | ready | running | paused | done | success | partial | failed
phase:  LIST_SEARCH | EDIT | CONFIRM_INFO | DONE
```

任务快照包含：

- `cursor`、`retry`、`current`
- `config`
- `skcs`、`queryType`、`runScopedSkcs`
- `imagePlan`、`frontCursor`、`usedFrontImages`
- `backMaterialNames`、`backPlanNames`
- `skcStatuses`、`xlsxMeta`
- `submitAttempt`、`error`、`logs`

### 3.3 轮播图批次状态

```js
{
  id, stage: 'start' | 'edit', status: 'running' | 'done' | 'failed' | 'stopped',
  cancelled: false,
  ids: ['9542570366', '45687392555'],
  index: 0,                       // 当前处理的零基下标
  results: [
    { id, status: 'drill' | 'submitted' | 'submit-pending', wraps, counts, at }
  ],
  deleteIndex: 5,
  addImages: true,
  dryRun: true,
  cropW: 1350,
  cropH: 1800,
  progress: '',
  error: '',
  createdAt, updatedAt
}
```

### 3.4 租约

使用 `localStorage`：

```text
temu-image-bot-task-lease-v2:<windowId>
temu-image-bot-task-lease-v2:task:<taskId>
```

租约 25 秒有效，5 秒心跳续租。用于阻止同一任务在多个标签页同时运行。

## 4. 商品图片编辑状态机

### 4.1 主流程

```text
LIST_SEARCH
  → 查询 SKC/SPU
  → 找到 SPU
  → EDIT（打开商品编辑页）
  → 新增色值/货号/图片/属性/SKU
  → 提交
  → CONFIRM_INFO（商品信息确认页，如有）
  → 回列表核对状态
  → 下一个 ID
  → DONE
```

### 4.2 任务队列

- `taskLibrary` 保存多个货号任务。
- 用户逐任务“保存准备”，状态变为 `ready`。
- “开始队列”只取 `ready` 任务，按列表顺序执行。
- 当前任务运行期间，其他标签页通过租约看到 `leaseBlocked`，保持只读。
- 任务完成后按成功/失败数生成 `success | partial | failed`。

### 4.3 失败重试与超时

- 单商品失败自动重试 1 次。
- 图片合规异常不盲目重试，记录 `IMAGE_QUALITY_REJECTED`。
- 连续无进展超过 `skuTimeoutMin` 分钟，标记“卡死超时”，跳过当前商品。
- 提交结果未确认时标记待确认，不进入自动重试。

## 5. 轮播图维护状态机

### 5.1 单 ID

```text
start
  → 当前页导航到 /material/image-task
  → 点击「发起图片/视频更新」
  → 输入当前 ID
  → 点击「确认」
  → 关闭自动打开的重复详情页
  → 当前页导航到 /goods/images-edit?productId=<ID>&from=selfTask
edit
  → 遍历所有 [class*="preview-image_wrap"]
  → 每个色值删除第 N 张
  → 如 addImages：打开素材中心 → 上传/选择 → 确认
  → dryRun ? 不提交 : 点击提交并等待成功
```

### 5.2 批量

```text
index=0
  → 处理 ids[0]
  → results[0] = { wraps, counts }
  → index=1, stage=start
  → 导航回 /material/image-task
  → 处理 ids[1]
  → ...
  → index=last, status=done, progress=全部完成 N/N
```

### 5.3 跨页续跑

`boot()` 完成后调用 `resumeCarouselJob()`：

- `stage=start` 且当前是 `/material/image-task` → 执行发起阶段。
- `stage=edit` 且当前是 `/goods/images-edit` → 执行删除/新增阶段。
- `status` 非 `running` 或 `cancelled=true` → 不续跑。

### 5.4 提交结果

- 点击提交后检查是否有确认弹窗；有则点“确认/确定”。
- 20 秒内检测：
  - 页面离开 `/goods/images-edit`；
  - 或出现“提交成功/更新成功/操作成功/已提交”。
- 未识别到成功 → `submit-pending`，停止批次，避免重复提交。

## 6. 页面自动化层

### 6.1 通用工具

| 函数 | 用途 |
| --- | --- |
| `waitFor(fn, {timeout, interval, desc})` | 轮询等待元素/状态 |
| `realClick(el)` | 合成 mousedown/mouseup/click，适合大多数 beast-core 按钮 |
| `trustedClick(el)` | `chrome.debugger` 真实鼠标点击，适合必须 trusted 的按钮 |
| `platformClick(el)` | `el.click()`；用于调试器受限窗口，规避访问限制 |
| `setInput(el, value)` | 原生 setter + input/change，失败回退真实输入 |
| `setInputCommitted` | 写值后 blur/focusout，确保 React 表单落盘 |
| `typeTextReal` | 调试器真实键盘输入 |
| `deepScrollIntoView` | 多层滚动容器中把目标滚到视口 |
| `dismissOverlays` | 关闭消息抽屉/遮挡弹层 |
| `clickInDialog(dlg, text)` | 在指定弹窗内点击按钮 |

### 6.2 主要选择器

| 页面 | 选择器/文本 |
| --- | --- |
| 商品列表 | `input[placeholder="多个查询请空格或逗号依次输入"]`、`查询` |
| 商品编辑 | `mainSpec[0]`、`carouselImgsI18n.common`、`upload-trigger_wrap` |
| 素材中心 | `MDL_innerWrapper` + `本地上传` + 非 `无需重复上传` |
| 裁剪 | `MDL_innerWrapper` + `待载剪/待保存` |
| 图片更新任务 | `发起图片/视频更新`、input placeholder `可输入SPU、SKC或SKC货号`、`确认` |
| 图片更新详情 | `[class*="preview-image_wrap"]`、`[class*="preview-image_productItem"]`、`[class*="preview-image_deleteIcon"]`、`[class*="upload-trigger_wrap"]`、`提交` |

选择器使用 `class*=` 前缀匹配，减少平台哈希类名变化影响。

## 7. 素材中心与图片处理

### 7.1 弹窗隔离

- `activeMaterialDialog` 绑定本次实际打开的弹窗。
- `materialDialog()` 优先返回仍连接、可见且占据视口中心的弹窗。
- `ownsViewportCenter()` 防止读到后台残留的“已选 0 个”弹窗。

### 7.2 数量校验

- `selectedCount(dlg)` 读取 `已选 N 个`。
- `selectCard(labelEl, dlg)` 每次点击后立即检查数量是否 +1。
- 如果没增加，依次尝试：选择框 → 缩略图 → 卡片上方 → 卡片中心。
- `isCardSelected(card)` 检查 `aria-selected/aria-checked/data-selected/checked/selected class`，已选卡片不再点击。

### 7.3 上传与裁剪

- 隐藏的 `input[type=file][multiple]` 通过 `DataTransfer` 赋值。
- 上传前 `ensureUploadableImage`：超过 1.9MB 自动转 JPEG 压缩。
- 出现裁剪弹窗时，`handleCropDialog(cropW, cropH)`：
  - 等尺寸输入加载；
  - 写入 1350×1800；
  - 逐张确认裁剪；
  - 点保存；
  - 等弹窗关闭。
- `dismissDedupeIfAny()` 处理“无需重复上传”，改为从素材库选。

### 7.4 选图

- `pickMaterial(dlg, fileOrName, { uploadIfMissing, cropW, cropH })`：
  1. 先在当前列表找；
  2. 搜索素材名称；
  3. 找不到则本地上传 + 裁剪；
  4. 等待素材入库并重新搜索；
  5. 选中并校验数量。
- 上传后的素材名可能带后缀（如 `icon128-33`），`findMaterialCard` 用 `^base(-\d+)?$` 兼容。

## 8. Excel 与状态回写

### 8.1 读取

- `parseXlsxDetailed`：解压 xlsx，读取 sharedStrings 和工作表 XML。
- `extractProductEntries`：识别 SKC ID/SPU ID 列和状态列。
- `extractSkcs`：无表头时提取 6–20 位数字。
- CSV/TXT：按文本正则提取 ID。
- 轮播图 ID 文件：xlsx 优先按 ID/货号表头取列；否则提取数字 ID；CSV/TXT 提取含数字的 4–40 位 token。

### 8.2 回写

- `buildStatusWorkbook`：
  - 复制原 xlsx 部件；
  - 在 headerIndex 的状态列写“状态”；
  - 按 entry.rowNumber 写入每个 ID 的最终状态；
  - 追加“运行汇总”工作表。
- 下载文件名：`<原文件名>-状态-<时间>.xlsx`。

### 8.3 模板

- `buildBlankWorkbook(sheets)` 从零构造最小 OOXML 包：

```text
[Content_Types].xml
_rels/.rels
xl/workbook.xml
xl/_rels/workbook.xml.rels
xl/worksheets/sheet1.xml
```

- 多色模板：工作表 `多色SKC清单`，表头 `多色 SKC ID`、`状态`。

## 9. 提交与结果核对

### 9.1 商品编辑提交

- 提交前关闭残留素材中心弹窗。
- 严格自检：色值、图片数量、货号、属性、体积重量、价格、库存、SKU。
- 点击提交后进入 `submitAttempt`，回列表核对：
  - 信息修改中 / 修改成功 → 成功；
  - 商品信息待确认 → 打开确认页；
  - 未识别 → 待确认，不自动重试。

### 9.2 轮播图提交

- `submitConfirmDialog()` 查找带“确认/确定”的提交弹窗。
- `waitForSubmitResult()` 等待页面跳转或成功文案。
- 未确认成功 → 停止批次并记录 `submit-pending`。

## 10. 可靠性与异常处理

| 异常 | 处理 |
| --- | --- |
| 图片品质不合规 | 全局检测弹窗，取消并抛出 `IMAGE_QUALITY_REJECTED` |
| 素材重复 | 选图前检查计划重复；已选卡片不重复点击 |
| 主图不足 | 准备阶段阻止开始 |
| 单商品失败 | 自动重试 1 次 |
| 连续无进展 | 超时后跳过当前商品，继续队列 |
| 提交结果未确认 | 标记待确认，不自动重试 |
| 页面跳转/刷新 | IndexedDB 恢复任务和轮播图批次，自动续跑 |
| 同任务多标签页 | localStorage 租约阻止并发 |
| 平台类名变化 | 前缀选择器 + 文本/占位符兜底 |

## 11. UI 实现

- Shadow DOM：`#temu-image-bot-host`，避免页面 CSS 污染。
- 主题：24 套预设 + 深色 + 自定义主色 + 透明度。
- 面板状态：`uiState` 保存 `theme/pos/panelSize/collapsed/closed/remark/view`。
- 拖动/缩放：标题栏或空白区拖动；右边缘/下边缘/右下角三个透明 resizer；左上角锚定。
- 缩小：`uiState.closed=true` → `.box` 隐藏，`.panelLauncher` 显示。
- 关闭：同样隐藏到悬浮按钮。
- 任务列表/详情：`home` / `detail` 视图；参数放在任务详情。

## 12. 多窗口与多店铺

- IndexedDB 按浏览器配置隔离。
- `GET_TAB_INFO` 获取 windowId/tabId。
- 店铺名从页面头部识别；窗口备注存 `ui.remark`。
- 任务租约同时写窗口级和任务级 key。
- 不同窗口可并行；同窗口同任务不可并行。

## 14. 已知限制

1. TEMU 页面 DOM/类名可能随平台发版变化，需要更新选择器。
2. `.xls` 旧二进制格式不支持；请另存为 `.xlsx`。
3. 轮播图正常提交后的成功文案未在本轮真机验证（按要求未点提交）；代码在无法确认成功时会停止批次并标记待确认。
4. 多色测试覆盖 4 个色值组；更多色值按同一循环处理，但尚未真机覆盖。
5. 部分比特浏览器窗口禁止 `chrome.debugger` 访问图片更新页；轮播图流程使用 `element.click()`，其他流程仍可能依赖调试器。
6. 平台可能虚拟化长列表；脚本会按当前 DOM 可见行处理。

## 15. 发布与文档同步

每次版本更新必须：

1. 修改 `manifest.json` 和 `main.js` 的版本号。
2. 更新 [CHANGELOG.md](./CHANGELOG.md)。
3. 行为变化 → 更新 [PRD.md](./PRD.md)。
4. 实现/选择器/数据模型变化 → 更新本文。
5. 使用方式变化 → 更新 [初次使用公告.md](./初次使用公告.md) 和 `extension/README.md`。
6. 运行 `python tools/build_release.py` 生成安装包和 Markdown 文档包；该脚本会先校验文档是否包含当前版本。

完整检查表见 [文档维护规范.md](./文档维护规范.md)。
