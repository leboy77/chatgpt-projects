# Temu 自动下架与图片保存扩展程序技术方案

文档版本：V1.2（纯扩展版已稳定）  
编写日期：2026-10-20  
当前状态：SPU 批量导入、页面内悬浮面板、主图归档和下架流程已实现

## 1. 已验证的环境事实

### 1.1 比特浏览器

实际验证结果：

| 项目 | 结果 |
|---|---|
| 本地 API | `http://127.0.0.1:54345` |
| 窗口查询接口 | `POST /browser/list` |
| 窗口打开接口 | `POST /browser/open` |
| 指定 ID | `9e6f73cc742b4abc9015f31f8e75fbd7` |
| 返回序号 | 7512 |
| 返回名称 | Y2-18 |
| 内核 | Chrome 148 |

打开窗口请求示例：

```http
POST http://127.0.0.1:54345/browser/open
Content-Type: application/json

{"id":"9e6f73cc742b4abc9015f31f8e75fbd7"}
```

返回数据中包含 `ws`、`http`、`seq`、`name`、`pid`。正式程序应优先使用 `id` 匹配，不把序号作为唯一键。

### 1.2 Temu 页面

已验证页面：

```text
https://agentseller.temu.com/material/image-task
https://agentseller.temu.com/goods/list
```

浏览器调试端口由比特浏览器动态分配，不能写死为示例中的端口。程序应从 `/browser/open` 返回的 `http` 或 `ws` 字段动态连接。

## 2. 总体架构建议

采用纯 Chrome MV3 扩展结构，不依赖 Windows 本地程序和固定本机端口：

```text
Excel 导入
    ↓
扩展侧边栏 / 弹窗
    ↓
任务调度器（Service Worker）
    ├── 可选比特浏览器 API
    ├── Temu 页面 Content Script
    ├── 图片下载与校验
    ├── 目录和文件写入
    └── 结果表导出
```

### 2.1 纯扩展能力与边界

纯浏览器扩展可以：

- 解析 Excel。
- 调用允许访问的本地比特浏览器 API。
- 通过 Content Script 操作 Temu 页面。
- 使用 File System Access API 写入用户授权的目录。
- 使用 `chrome.downloads` 回退到浏览器下载目录。
- 保存任务状态到扩展本地存储或 IndexedDB。

纯扩展不能无提示地写入任意绝对路径，因此首次可由用户选择父目录并授权。目录句柄存储在 IndexedDB；浏览器重启后若权限失效，需要用户再次授权。未选择目录时，自动使用浏览器下载目录，保证多开环境可以独立运行。

## 3. 模块设计

### 3.1 扩展界面

扩展在“图片/视频更新任务全球”页面内注入悬浮面板。面板使用隔离的 Shadow DOM 包裹 iframe，避免与 Temu 页面样式冲突；离开该页面后面板自动移除，返回时重新挂载。

面板提供 4 套皮肤，通过扩展页设置 `html[data-theme]`，再由 `postMessage` 同步外部标题栏。标题栏支持 Pointer Events 拖动，坐标保存在站点 localStorage 中，并在窗口尺寸变化时自动限制在可视区域内。

- Excel 文件选择，格式为“序号 / SPU ID / 状态”。
- 自动提取货号分类，并提供可选人工覆盖值。
- 高级设置中的 BitBrowser ID 配置，默认为空。
- 输出根目录配置。
- 处理模式：演练 / 保存图片 / 保存并下架。
- 批量开始、暂停、继续、停止。
- 表格展示每行状态和最近错误。
- 导出结果表。

### 3.2 任务调度器

职责：

- 生成任务队列。
- 保证单窗口串行处理。
- 实现超时、退避和有限重试。
- 持久化断点。
- 防止同一 SPU 重复提交。
- 失败项重试使用任务行筛选集合，只重新调度可重试状态。

每个任务建议使用状态机：

```text
QUEUED
  → SEARCHING
  → EXTRACTING
  → SAVING_IMAGES
  → OPENING_DOWNLIST
  → SUBMITTING
  → VERIFYING
  → DONE / FAILED / MANUAL_REVIEW
```

### 3.3 Temu 页面适配层

所有页面选择器集中在适配层，不分散到业务代码。优先使用：

- 稳定文本。
- Placeholder。
- `data-testid`。
- 表单标签与相邻控件关系。
- 表格行内 SPU/SKC 文本。

避免依赖带哈希的 CSS Module 类名，例如 `index-module__text___2OBhR`。

## 4. 已验证的页面交互

### 4.1 查询 SPU

执行查询前，先点击任务状态栏中的“全部”。不能直接沿用页面默认的“待更新”栏，否则部分存在于其他状态的 SPU 会被漏查。

图片任务页已验证元素：

```text
查询类型下拉框：支持 "SPU" 和 "SKC" 两个选项
当前批次使用：value = "SPU"
编号输入框：placeholder = "批量查询按照空格/逗号隔开，单次支持20个"
查询按钮：文本 = "查询"
```

虽然页面支持一次输入最多 20 个编号，用户当前要求是逐个输入并等待结果。首版应串行处理，避免批量结果分页或多值造成错配。Excel 输入使用 SPU ID，查询类型必须切换为 SPU。

等待条件不能只使用固定 `sleep`。应等待以下条件之一：

- 出现包含当前 SPU 的结果行。
- 出现明确的“暂无数据”状态。
- 超时。

### 4.2 提取商品字段

目标行已确认包含：

```text
SPU: 8780418723
货号: CXTX9
轮播图-混合色（货品SKC：10666358927）
```

建议正则：

```text
货号[：:]\s*([^\s]+)
货品SKC[：:]\s*(\d+)
```

注意：

- 页面中“SKU ID”和“SKC ID”不是同一概念。
- 输入使用 Excel 的 SKC，页面素材信息中的“货品SKC”用于复核。
- 从结果行提取 SPU，用于主图文件命名。
- 从结果行提取货号，并与插件必填货号核对。
- 页面货号与插件货号不一致时停止该行。

### 4.3 主图

目标行商品信息中已定位主图 URL，缩略图形式类似：

```text
https://img.kwcdn.com/product/open/{文件标识}-goods.jpeg?imageMogr2/thumbnail/60x
```

下载原图时移除 `?imageMogr2/...`：

```text
https://img.kwcdn.com/product/open/{文件标识}-goods.jpeg
```

已验证当前主图原图：

```text
格式：JPEG
尺寸：1340 × 1785
大小：550205 字节
```

建议使用两层校验：

1. 响应层：HTTP 200、图片 MIME、非零长度。
2. 解码层：图片宽高有效、格式受支持、文件哈希非空。

当前新版 Temu 页面使用虚拟图片渲染，缩略图可能不在常规 `<img>` DOM 中立即出现。程序通过页面主世界的 React 数据桥接读取查询记录中的 `mainUrl`，直接取得原图地址；DOM 缩略图仅作为兼容回退。

### 4.4 下架入口

页面中点击：

```text
文本 = "商品下架"
文本 = "发商品"
```

“发商品”是链接文本。点击后出现标题为“发送下架商品信息”的表单。

表单控件：

```text
类型：SKC ID
输入框：placeholder = "请输入完整SKC ID"
原因：label = "下架原因"
原因选项：文本 = "亏损下架"
提交按钮：文本 = "申请下架"
```

原因控件是只读输入框。不要按照“页面上最后一个输入框”选择，应先定位标签“下架原因”所在表单项，再在其内部查找选择控件。

### 4.5 二次确认

点击“申请下架”后出现二次确认：

```text
确认下架？
商品下架后，可能因各类因素影响而无法再次上架销售，造成不可逆的损失。
确认
取消
```

确认按钮有倒计时。自动化必须：

- 等待按钮可用。
- 重新确认 SKC 和原因。
- 按用户授权决定是否点击。
- 不使用页面文本模糊匹配点击“确认”，以免误点其他弹窗。

### 4.6 成功和失败识别

成功消息已实测：

```text
【SKC ID：10666358927】：您好，该商品已下架
```

失败消息已实测：

```text
非常抱歉操作失败，系统忙碌中，请您稍后重试
```

风险：聊天窗口保留历史失败记录，不能把页面中曾出现过的成功字符串当成当前任务成功。应记录提交前的消息数量或最后一条消息节点，只检查提交后新增的消息。

### 4.7 结果核验

下架后打开：

```text
https://agentseller.temu.com/goods/list
```

输入 SKC，查询，并切换“已下架/已终止”。实测目标商品出现在该分类，页面显示“未在售，暂无价格”。

因为页面状态更新存在异步延迟，建议：

1. 收到客服成功消息。
2. 等待 2 至 5 秒。
3. 商品列表按 SKC 查询。
4. 检查“已下架/已终止”分类。
5. 分类未更新时再退避查询，不立即重复提交下架。

## 5. Excel 与货号处理

可使用随扩展打包的 SheetJS 读取 `.xlsx`，避免将用户文件上传到服务器。

处理步骤：

1. `File.arrayBuffer()` 读取。
2. 解析第一个有效工作表。
3. 识别 A 列“序号”、B 列“SPU ID”、C 列“状态”。
4. 将 SPU 统一转换为字符串，禁止科学计数法。
5. 跳过 SPU 为空的预留行，即使该行已有模板序号；校验和去重。
6. 读取插件中的必填货号；货号为空时禁止开始。
7. 生成任务 ID：`SPU + 行号`。
8. 将任务和批次货号写入 IndexedDB。

扩展包内置 `templates/下架SPU模板.xlsx`，预填 100 行序号，B 列统一按文本格式保存。插件侧边栏通过 `chrome.downloads` 下载该模板，打包脚本必须包含 `templates` 目录。

结果表建议字段：

```text
行号
SPU
插件货号
页面货号
SKC
主图路径
主图是否复用
图片结果
下架结果
平台返回
商品列表核验
尝试次数
开始时间
结束时间
错误代码
错误详情
```

## 6. 文件系统方案

### 6.1 纯扩展推荐实现

使用 `chrome.downloads.download`：

目标目录结构：

```text
用户选择的父目录/下架图片合集/CXTX/
├── 主图保存/
│   └── 8780418723_主图_01.jpeg
└── 背面图保存/
```

纯扩展回退方式只保存到浏览器下载目录：

```json
{
  "url": "图片原图 URL",
  "filename": "下架图片合集/CXTX/主图保存/8780418723_主图_01.jpeg",
  "conflictAction": "uniquify",
  "saveAs": false
}
```

优点：

- 无需本地服务。
- 安装和使用简单。
- 文件名和子目录可完全自动。

限制：

- 根目录固定为浏览器下载目录。
- 扩展无法直接访问 `DownloadItem` 的绝对文件路径。
- 图片校验在写入前通过 Blob 解码完成。

### 6.2 需要任意路径时

可使用 File System Access API：

1. 用户在扩展页面选择根目录。
2. 保存 `FileSystemDirectoryHandle` 到 IndexedDB。
3. 每次运行检查权限。
4. 自动创建子目录并写入 Blob。

该方案不影响纯扩展部署，但目录权限可能因浏览器重启失效，需要再次授权。

### 6.3 当前纯扩展实现

- 优先使用 File System Access API 写入用户选择的父目录。
- 用户选择桌面或其他父目录后，插件创建 `下架图片合集`。
- 未选择目录或权限失效时，使用 `chrome.downloads` 保存到浏览器下载目录。
- 图片先下载为 Blob，并校验尺寸和 SHA256，再写入文件。
- 每个浏览器实例独立保存设置和目录句柄，不共用端口或后台进程。

## 7. 浏览器连接

### 7.1 打开窗口

扩展通过后台请求：

```javascript
fetch("http://127.0.0.1:54345/browser/open", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ id: browserId })
});
```

该请求默认不执行。普通 Chrome 和已打开的目标比特窗口直接使用当前 Temu 页面；只有高级设置填写 BitBrowser ID 时才尝试打开对应窗口。打开失败时自动回退当前页面，不阻塞文件归档任务。

需要：

- 在 `host_permissions` 中仅允许 `http://127.0.0.1:54345/*`。
- 校验响应 `success === true`。
- 校验返回的序号和名称。
- 不存储账号密码或 Cookie。

### 7.2 页面控制

若扩展运行在目标比特浏览器窗口内，可直接使用 Content Script 操作当前标签页。

若扩展运行在其他 Chrome 中，仅调用 `/browser/open` 不足以获得页面控制权；需要将前端校验拆分为两种部署模式：

1. 扩展安装在指定的比特浏览器环境内。
2. 扩展运行在目标比特浏览器窗口内。

当前推荐第 1 种，因为最符合浏览器扩展的使用方式。

## 8. 页面适配设计

### 8.1 选择器优先级

建议封装函数：

```text
findButtonByText(scope, "查询")
findInputByPlaceholder(scope, /完整SKC ID/)
findFormItemByLabel(scope, "下架原因")
findTableRowByText(scope, spu)
```

### 8.2 DOM 更新监听

不要依赖固定 1 秒等待。使用：

- `MutationObserver` 观察结果表和聊天消息容器。
- `requestAnimationFrame` 处理短动画。
- 业务超时，例如搜索 15 秒、下架结果 60 秒。
- 每次等待返回明确条件，而不是无限轮询。

### 8.3 错误码建议

| 错误码 | 说明 |
|---|---|
| BB_API_UNAVAILABLE | 比特浏览器本地 API 不可用 |
| BB_PROFILE_MISMATCH | 返回的浏览器 ID、名称或序号不匹配 |
| TEMU_LOGIN_REQUIRED | 未登录或登录失效 |
| TEMU_CAPTCHA | 出现验证码或人机校验 |
| SKC_NOT_FOUND | 查询无结果 |
| SKC_AMBIGUOUS | 同 SKC 多行或查询结果不唯一 |
| HK_REQUIRED | 插件货号为空 |
| HK_MISMATCH | 插件货号与页面货号不一致 |
| SKC_INVALID | SKC 为空或格式错误 |
| MAIN_IMAGE_MISSING | 主图未找到 |
| IMAGE_DOWNLOAD_FAILED | 图片下载或校验失败 |
| FOLDER_CREATE_FAILED | 自定义目录或下载目录创建失败 |
| TEMPLATE_DOWNLOAD_FAILED | 下架 SPU 模板下载失败 |
| DOWNLIST_FORM_NOT_OPEN | 下架表单未出现 |
| DOWNLIST_BUSY | 平台返回系统忙碌 |
| DOWNLIST_REJECTED | 平台拒绝 |
| DOWNLIST_VERIFY_FAILED | 成功消息与列表状态不一致 |
| PAGE_STRUCTURE_CHANGED | 关键元素发生变化 |

## 9. 幂等与重试

### 9.1 幂等

- 已完成 SKC 默认不再处理。
- 图片保存成功、下架失败时，重试只走下架阶段。
- 主图以 SPU 为幂等键；同一批多个 SKC 对应同一 SPU 时只保存一次并复用。
- 已收到成功消息但列表未刷新时，先核验，不重复提交。
- 从 IndexedDB 恢复时检查任务阶段。
- “重试失败项”仅纳入状态包含“未查到、超时、处理失败、下架失败”的行。
- “需复核”不自动重试，防止状态不明确时重复下架。
- 页面消息使用 45 秒查询超时、150 秒下架超时和 35 秒核验超时。
- 图片下载使用 30 秒网络超时，浏览器下载等待使用 60 秒超时。
- 下架阶段超时只跳过并标记需复核，禁止自动重提。
- 上述超时可通过高级设置调整；参数保存在 `chrome.storage.local`，每个浏览器实例独立。

### 9.2 重试

建议默认：

- 网络请求：3 次，指数退避。
- 图片下载：3 次。
- 平台“系统忙碌”：3 次，每次间隔 15 秒。
- 页面结构变化：不盲目重试，停止批次并转人工。
- 下架提交阶段：每次重新确认当前 SKC，禁止跨任务使用旧表单。

## 10. 安全与合规

- 只在本地运行，不将 Excel、商品信息或图片上传到第三方服务器。
- 不读取、不导出比特浏览器保存的账号密码。
- 不收集 Cookie。
- 不调用 Temu 未公开的内部下单或商品变更接口。
- 所有下架操作基于可见页面和用户授权。
- 日志中隐藏账号、Cookie、浏览器代理等敏感信息。
- 正式版本增加醒目提示：下架可能无法恢复。

## 11. 测试计划

### 11.1 单元测试

- SKC 文本规范化。
- Excel 表头识别、空行和重复行。
- 货号分类和输出目录生成。
- SKC 正则提取。
- 图片 URL 去裁剪参数。
- 成功/失败消息分类。
- 错误码映射。

### 11.2 集成测试

- 比特浏览器 API 正常、不可用、ID 不存在。
- 已登录、未登录、验证码状态。
- 单 SPU 查询成功、无结果、多结果。
- 主图下载成功、图片 404、HTML 错误页、尺寸异常。
- 下架成功、系统忙碌、平台拒绝。
- 客服成功但商品列表延迟。
- 中断后继续。

### 11.3 验收试跑

正式开发前，建议约定 5 个 SPU：

- 1 个主图正常。
- 1 个系统忙碌。
- 1 个 SKC 无权限或不存在。
- 1 个重复行。
- 1 个货号为空、页面货号不一致、主图下载失败。

首轮必须使用演练模式；用户确认结果后，再开启一个真实下架样本。

## 12. 当前实现风险

| 风险 | 影响 | 建议 |
|---|---|---|
| 序号 7515 与 ID 对应序号 7512 不一致 | 可能误开其他窗口 | 以 ID 为唯一键，显示实际名称和序号 |
| 文件目录权限可能失效 | 浏览器重启后需要再次授权 | 重新选择同一目录 |
| Excel 只有 SKC、没有货号 | 无法正确分类目录 | 货号设为批次必填参数并核对页面货号 |
| 页面 DOM 会更新 | 选择器失效或误点 | 集中适配层、启动前自检 |
| 聊天历史含旧失败消息 | 误判成功 | 仅检查提交后新增消息 |
| 下架不可逆 | 业务损失 | 双重确认、默认演练、结果核验 |
| 多开实例共用下载目录 | 同名文件可能互相覆盖 | 建议每个店铺选择独立文件夹 |
| 平台限流或系统忙碌 | 批处理中断 | 串行、退避、有限重试 |
| 图片 CDN 变更 | 下载失败 | URL 获取与下载分层，保存结果可重试 |
| 自动修改背图目录 | 覆盖运营模板 | 程序对背图目录只创建、不写入 |

## 13. 开发前确认门槛

需求文档第 14 节的 10 项全部确认后，再进入正式开发。特别是以下三项会直接改变架构或业务结果：

1. 每个店铺是否使用独立保存目录。
2. Excel C 列状态是导出新表还是原地更新。
3. 真实下架是否允许整批自动提交最终确认。
