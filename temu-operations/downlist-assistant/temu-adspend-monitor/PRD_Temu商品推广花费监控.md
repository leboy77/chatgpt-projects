# PRD：Temu 商品推广实时花费监控与自动暂停

文档版本：V0.1  
编写日期：2026-10-22  
目标窗口：比特浏览器 `9e6f73cc742b4abc9015f31f8e75fbd7`，序号 `7512`，名称 `Y2-18`  
当前阶段：需求定型、真实只读探测和虚拟选型已完成，尚未执行真实暂停

## 1. 项目概述

运营人员需要在 Temu 广告后台持续查看各 SPU 的今日花费和每单花费，并在花费达到设定的风控线后暂停对应商品推广，避免广告继续超支。

本扩展将运行在“商品推广”页面，通过可配置秒级刷新周期读取页面同源数据，在本地判断每个 SPU 是否触发规则。默认只告警和演练；只有用户明确开启自动暂停并确认规则后，才允许调用页面的推广暂停能力。

核心价值：

- 不必反复刷新整个网页。
- 可按 SPU 设置花费上限和每单花费上限。
- 命中阈值后自动暂停，并二次读取状态核验。
- 全程保留审计记录，异常时不盲目重复操作。

## 2. 需求解释与已采用假设

用户同时提到“每单花费参数”和“一个 SPU 的花费超过自定义的花费标准”。为避免只支持一种口径，V1 同时提供两类可选规则：

| 规则 | 计算口径 | 说明 |
|---|---|---|
| 今日花费上限 | 同一 SPU 的今日总花费 | 只要累计花费达到阈值即触发 |
| 每单花费上限 | 同一 SPU 的今日总花费 ÷ 今日成交订单数 | 订单数为 0 时不判断该规则，避免除零和误判 |

一个 SPU 可能对应多条推广记录。监控时先按 `SPU ID` 聚合花费和订单量，再统一判断；命中后暂停该 SPU 下满足安全条件的全部在投推广记录。

两类规则均可选：

- 值为 `0` 或留空表示停用。
- 两类规则同时启用时采用“或”关系，任意一项达到阈值即触发。
- V1 使用“大于或等于”判断，避免因金额按分取整而跨过阈值后仍不触发。

## 3. 用户与使用场景

### 3.1 主要用户

- 店铺运营：配置每个 SPU 的今日花费和每单花费上限。
- 投放负责人：观察触发记录、复核暂停结果。
- 店铺管理员：决定是否开启真实自动暂停。

### 3.2 使用场景

1. 运营打开“Temu 广告后台 → 商品推广”。
2. 扩展自动识别当前页面和店铺。
3. 运营设置刷新秒数，例如每 60 秒读取一次。
4. 运营为指定 SPU 设置今日花费上限，例如 `¥50`，也可设置每单花费上限，例如 `¥20`。
5. 扩展按周期读取花费并更新列表。
6. 达到阈值时，默认弹出告警；开启自动暂停后，扩展暂停该 SPU 的推广。
7. 扩展重新读取推广状态，确认状态变为“已暂停”。
8. 记录触发时间、阈值、当时花费、订单数、每单花费、暂停结果和核验结果。

## 4. 产品目标

### 4.1 必须实现

- 以秒为单位配置刷新间隔。
- 可对任意 SPU 设置独立的今日花费上限和每单花费上限。
- 无需刷新整个网页即可读取最新推广数据。
- 阈值命中后默认告警；经授权后可自动暂停。
- 暂停后重新读取接口，核验状态确已变为手动暂停。
- 同一 SPU、同一规则、同一自然日只自动执行一次暂停。
- 支持观察模式、自动暂停模式和全局停止。
- 显示数据更新时间、最近检查时间和本次读取耗时。

### 4.2 首版不做

- 不自动恢复或重启推广。
- 不修改预算、ROAS、价格、库存或商品信息。
- 不自动创建推广。
- 不自动处理验证码、人机校验或账号登录。
- 不跨店铺汇总数据。
- 不绕过 Temu 页面权限或风控。
- 不以 DOM 文本作为主要花费数据源。

## 5. 数据定义

Temu 接口中的金额字段以整数“分”返回，展示字段同时提供 `trans_val`。例如推广日预算 `10000` 对应 `¥100.00`。

### 5.1 今日花费

```text
SPU 今日花费（元） = Σ 该 SPU 当前推广记录的 spend.total.val / 100
```

### 5.2 今日订单数

```text
SPU 今日订单数 = Σ 该 SPU 当前推广记录的 order_pay_cnt.total.val
```

### 5.3 每单花费

```text
SPU 每单花费（元） = SPU 今日花费（元） / SPU 今日订单数
```

当订单数为 `0` 时，每单花费显示为“暂无”，不触发每单花费规则。

### 5.4 规则命中

```text
今日花费命中 = 今日花费上限 > 0 且 今日花费 >= 今日花费上限
每单花费命中 = 每单花费上限 > 0 且 今日订单数 > 0 且 每单花费 >= 每单花费上限
最终命中 = 今日花费命中 或 每单花费命中
```

### 5.5 推广状态

页面状态枚举已确认：

| 代码 | 状态 | 是否可自动暂停 |
|---:|---|---|
| 8 | 推广中 | 是 |
| 7 | 手动暂停 | 否，已暂停 |
| 0 | 余额不足 | 否 |
| 1 | 日预算达到上限 | 否 |
| 2 | 售罄 | 否 |
| 3 | 商品已移除 | 否 |
| 4 | 审核中 | 否，保守跳过 |
| 5 | 审核驳回 | 否 |
| 6 | 推广受限 | 否 |
| 9 | 已删除 | 否 |
| 12 | ROAS 限制 | 否 |
| 14 | 月度限制 | 否 |
| 15 | 商品数量限制 | 否 |

自动暂停只处理“推广中”记录。接口返回未知状态时转人工复核，不执行暂停。

## 6. 功能需求

### 6.1 监控设置

| 字段 | 类型 | 默认值 | 约束 |
|---|---|---:|---|
| 刷新间隔 | 整数秒 | 60 | 30–3600 秒 |
| 今日花费上限 | 金额 | 未启用 | 大于等于 0，精确到分 |
| 每单花费上限 | 金额 | 未启用 | 大于等于 0，精确到分 |
| 自动暂停 | 开关 | 关闭 | 开启前必须展示风险确认 |
| 单次读取超时 | 整数秒 | 20 | 5–60 秒 |

刷新间隔低于 30 秒时提示“平台数据更新通常有延迟，过短间隔不会带来更高实时性”。

### 6.1.1 页面锁定

- 扩展只在 `https://ads.temu.com/ad-list.html` 启用。
- 首次在推广页打开扩展时，锁定当前标签页的窗口和标签页 ID。
- 后续读取、暂停和恢复操作始终发送给锁定的推广标签页。
- 切换浏览器活动标签页时，扩展不跟随切换到其他网页。
- 锁定标签页离开推广页、跳转到其他网站或关闭时，立即停止监控并取消锁定。
- 扩展不得在其他 Temu 页面、商家后台页面或第三方网页读取数据。
- 锁定的推广页离开后，扩展必须立即移除页面内悬浮窗。
- 非商品推广页不得显示扩展按钮入口或自动弹出悬浮窗。
- 用户回到推广页后可点击“锁定页面”重新建立锁定。

### 6.2 SPU 规则管理

每条规则至少包含：

- SPU ID。
- 今日花费上限。
- 每单花费上限。
- 是否启用。
- 规则备注。
- 最近触发时间。
- 今日是否已经自动暂停。

用户可以从当前接口读取到的推广记录直接添加规则。V1 不要求导入 Excel。

### 6.3 实时列表

列表字段：

- 商品标题。
- SPU ID。
- 商品 ID。
- 推广 ID。
- 当前状态。
- 今日花费。
- 今日订单数。
- 每单花费。
- 今日花费上限。
- 每单花费上限。
- 最近检查时间。
- 暂停结果。

列表顶部显示：

- 当前店铺/站点。
- 数据开始与结束时间。
- 最近检查时间。
- 平台数据更新时间（如接口提供）。
- 本次请求耗时。
- 监控运行状态。

### 6.4 刷新与读取

- 不执行 `location.reload()`。
- 不反复点击页面的“刷新数据”按钮。
- 在商品推广页面上下文中直接请求页面同源数据接口。
- 单次读取失败时先指数退避，不立即连续重试。
- 连续 3 次失败后暂停监控并显示错误。
- 页面离开、登录失效或出现人机校验时停止读取。

### 6.5 告警

观察模式下命中阈值时：

- 面板中该 SPU 行高亮。
- 记录一条“命中但未暂停”的审计事件。
- 可选桌面通知。
- 不调用暂停接口。

### 6.6 自动暂停

自动暂停必须满足全部条件：

1. 用户已经开启自动暂停。
2. 当前页面通过健康检查。
3. 数据请求成功且数据时间未异常。
4. 至少一条规则的数值达到阈值。
5. 目标记录状态为“推广中”。
6. 当前 SPU 今日没有成功的自动暂停记录。
7. 当前没有其他暂停请求正在执行。

执行顺序：

1. 固化触发快照。
2. 向暂停接口提交该 SPU 下全部“推广中”记录。
3. 读取接口响应及失败映射。
4. 等待 2–5 秒后重新读取。
5. 状态为“手动暂停”时标记成功。
6. 状态未变化时只允许一次核验重试，不连续重复提交。
7. 状态无法确认时标记“需人工复核”。

### 6.7 停止与恢复

- 点击“停止监控”后不再发起新请求。
- 已经发出的暂停请求等待响应并核验。
- 重新打开面板后保留设置和审计记录。
- 系统不会因服务重启而自动恢复推广。

### 6.8 暂停记录与手动恢复

- 扩展自动暂停成功后，必须记录被暂停的 SPU ID、商品 ID、暂停时间、当时花费、订单数和每单花费。
- 面板提供“已暂停 SPU 记录”框，按时间倒序展示记录。
- 每条尚未恢复的记录提供“恢复被暂停的投流”按钮。
- 恢复前必须提示：恢复后推广可能继续产生费用。
- 恢复请求使用页面现有推广开启能力。
- 恢复后重新读取推广明细，只有状态变为“推广中”才标记恢复成功。
- 已恢复记录继续保留，不自动删除。
- 系统不会在无人点击按钮的情况下自动恢复推广。

## 7. 页面与交互

扩展使用商品推广页面内的悬浮窗。悬浮窗默认约 `380 × 620`，支持拖动、最小化和位置记忆，不占用浏览器侧边栏，也不压缩页面宽度。

面板分为三个区域：

1. 控制区：刷新秒数、自动暂停开关、开始/停止、手动刷新。
2. 规则区：当前 SPU 阈值的新增、编辑和删除。
3. 运行区：今日花费、每单花费、状态、最近检查时间、异常和审计。

自动暂停开关第一次打开时显示：

```text
开启后，达到规则的 SPU 将被自动暂停。推广暂停可能影响在投流量，扩展不会自动恢复。
```

用户必须勾选“我已确认测试 SPU 和阈值”后才能继续。

## 8. 异常处理

| 场景 | 处理 |
|---|---|
| 页面未登录 | 停止轮询，提示登录，不重试写操作 |
| 出现验证码或人机校验 | 停止轮询，转人工 |
| 离开推广页或切换网页 | 立即停止轮询，取消页面锁定，不读取新页面 |
| 请求超时 | 指数退避，最多连续 3 次 |
| HTTP 429 | 延长到至少 5 分钟，暂停自动写操作 |
| 返回结构变化 | 停止监控，记录契约错误 |
| 金额为负或非数字 | 不判断、不暂停，标记数据异常 |
| 订单数为 0 | 不触发每单花费规则 |
| 状态不是推广中 | 跳过并记录原因 |
| 暂停响应成功但状态未变 | 等待后核验一次，再转人工 |
| 暂停网络超时 | 先重新读取状态；确认未暂停后才允许重试 |
| 同一 SPU 多条记录 | 聚合判断，批量暂停全部推广中记录 |

## 9. 审计与隐私

每条审计记录包含：

- 时间。
- 浏览器窗口 ID。
- SPU ID。
- 推广 ID。
- 今日花费。
- 订单数。
- 每单花费。
- 命中的规则。
- 阈值。
- 模式：观察或自动暂停。
- 操作结果。
- 核验结果。
- 错误码。

不得记录：

- Cookie。
- 请求签名。
- 账号密码。
- 与业务无关的完整页面内容。

审计数据只保存在扩展本地存储或 IndexedDB。

## 10. 验收标准

### 10.1 数据读取

1. 在商品推广页直接读取今日数据，不刷新整个网页。
2. 当前测试店铺可读取全部 19 条推广记录。
3. 正常网络下单次读取通常小于 2 秒。
4. 金额按分换算正确，例如预算 `10000` 显示为 `¥100.00`。
5. 当前窗口的 19 条记录均能取得 SPU ID。

### 10.2 规则

1. 今日花费达到上限时命中。
2. 每单花费达到上限且订单数大于 0 时命中。
3. 订单数为 0 时不触发每单花费规则。
4. 未达到阈值时不暂停。
5. 关闭规则后不再触发。

### 10.3 安全与幂等

1. 观察模式绝不调用暂停接口。
2. 同一 SPU 同一天只自动暂停一次。
3. 已暂停、审核中、异常和其他非推广中状态不自动暂停。
4. 暂停后能够通过重新读取确认状态为代码 `7`。
5. 请求失败或结果不明确时不会盲目重提。
6. 暂停记录能够准确显示扩展暂停过的 SPU ID。
7. 恢复成功后能够通过重新读取确认状态为代码 `8`。

### 10.4 运行

1. 刷新秒数修改后从下一次调度起生效。
2. 停止监控后不再发起请求。
3. 页面关闭或离开后自动停止。
4. 连续错误会停止并提示，不无限重试。

## 11. 真实暂停测试门槛

当前只完成了只读 fetch 和页面刷新链路验证，没有对真实推广执行暂停。

正式启用自动暂停前，必须由用户指定：

- 1 个允许测试的 SPU。
- 测试日花费上限或每单花费上限。
- 是否允许该 SPU 在达到阈值后真实暂停。

建议先使用一个当前未产生花费、可人工恢复的测试 SPU，并验证：

1. 自动暂停请求只执行一次。
2. 返回结果与页面状态一致。
3. 重新读取后状态为代码 `7`。
4. 审计记录完整。

## 12. 成功指标

- 有效数据读取成功率不低于 99%。
- 单次读取 P95 不高于 2 秒。
- 阈值命中识别准确率 100%。
- 自动暂停重复执行次数为 0。
- 暂停结果可核验率 100%。
- 默认设置下不会发生真实暂停。
