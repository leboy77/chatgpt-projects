# Temu 自动下架与图片保存扩展程序需求文档

文档版本：V1.2（纯扩展版已稳定）  
编写日期：2026-10-20  
当前阶段：需求澄清与流程验证，尚未进入程序开发

## 1. 项目背景

运营人员需要根据 Excel 或插件输入框中的一批 SPU ID，逐个完成以下操作：

1. 在 Temu 商家后台查询商品信息。
2. 按货号创建主图和背面图保存目录。
3. 下载商品图片并归档。
4. 从素材信息中取得完整 SKC ID。
5. 通过 Temu 官方客服自助工具申请下架商品，原因统一选择“亏损下架”。
6. 直接在当前“图片/视频更新任务全球”页面打开操作面板。

当前流程需要人工重复查询、复制编号、下载图片和填写客服表单，效率较低且容易产生错配。目标是开发一个在比特浏览器中使用的扩展程序，将上述流程串联为可追踪、可重试、可核验的批处理任务。

## 2. 项目目标

### 2.1 业务目标

- 从 Excel 或插件文本框批量读取 SPU ID。
- 将货号作为整批任务的必填参数。
- 按约定规则自动创建目录并保存商品图片。
- 自动查询并提取货号、SKC ID 和主图原图。
- 自动提交“亏损下架”申请。
- 对每个 SPU 输出明确的处理结果，便于运营复核。
- 支持只重试失败项目，不重复处理成功项。
- 页面内面板支持经典橙、深海蓝、森林绿、暖阳金 4 套皮肤。
- 面板可以自由拖动，并记忆上次位置。
- 对失败项提供准确原因，并支持安全重试。

### 2.2 非目标

首版不处理以下事项：

- 自动登录、处理验证码或绕过人机验证。
- 自动恢复已下架商品。
- 自动下载、生成或替换背面图。
- 修改价格、库存、商品标题、详情描述或其他商品资料。
- 使用 Temu 非公开接口替代页面操作。
- 多窗口、多店铺并行下架。

## 4. 术语

| 术语 | 含义 |
|---|---|
| SPU | 商品统一编号，例如 `8780418723` |
| SKC | 商品颜色/款式级货品编号，例如 `10666358927` |
| 参数 A / 货号 | 用于目录命名，也是插件中的整批必填参数，例如 `CXTX9` |
| 主图 | 图片/视频更新任务列表“商品信息”中显示的商品图片 |
| 背面图 | 每个货号可复用的模板图片，由运营人工维护，程序不下载 |
| 批处理 | 按 Excel 行顺序逐个执行 SPU 任务 |

## 5. 输入要求

### 5.1 Excel 格式

用户提供的表格格式为：

| 列名 | 是否必填 | 类型 | 说明 |
|---|---|---|---|
| A 列：序号 | 否 | 整数 | 用于展示和结果排序 |
| B 列：SPU ID | 是 | 文本 | 不允许用科学计数法保存 |
| C 列：状态 | 否 | 文本 | 初始可为空，用于记录处理结果 |

插件内置 `下架SPU模板.xlsx`，模板预填 `1-100` 序号和 100 条空白数据行。用户只需填写 B 列 SPU ID；未填写 SPU 的预留行必须自动跳过，不能生成“空 SPU 格式异常”任务。

插件同时提供“直接填写 SPU ID”文本框，支持换行、空格、逗号、中文逗号、分号分隔。系统只接受 8-20 位数字 SPU，自动去重并忽略序号；直接输入的数据与 Excel 导入使用相同的任务结构、处理流程和结果导出功能。

首版限制：

- 一次性导入数量建议不超过 100 条，后续根据平台稳定性调整。
- 同一 SPU 在表中重复时，只执行一次，并在结果中标记重复。
- 空白行、非数字 SPU、长度异常的 SPU 应在启动前拦截。
- Excel 原表默认不直接修改；程序导出带状态的新 Excel，避免原数据损坏。
- 货号不在 Excel 中读取，由插件“货号”必填参数统一提供。

## 6. 输出目录和文件规则

### 6.1 目录结构

用户可以选择桌面或其他父目录，插件在其中创建“下架图片合集”。未选择目录时，保存到浏览器下载目录：

```text
用户选择的父目录/
└── 下架图片合集/
    └── {货号分类}/
        ├── 主图保存/
        └── 背面图保存/
```

以货号 `CXTX9` 为例：

```text
浏览器下载目录/
└── 下架图片合集/
    └── CXTX/
        ├── 主图保存/
        └── 背面图保存/
```

目录要求：

- 货号分类由页面查询结果自动获取。
- 一张 Excel 可以包含多个货号分类。
- 目录名称必须清理系统不允许的字符：`\ / : * ? " < > |`。
- 货号目录已存在时继续复用。
- “背面图保存”目录只创建，不自动下载或覆盖图片。
- 运营手工放入的背面图模板必须保留，程序不得清空该目录。

### 6.2 图片文件命名

建议格式：

```text
{SPU}_主图_01.{扩展名}
```

当前试跑保存的文件为：

```text
8780418723_主图_01.jpeg
```

每个 SPU 只保存一张主图。如果同一批 Excel 中多个 SKC 属于同一个 SPU：

- 下架按 SKC 逐个执行。
- 主图按 SPU 去重，只下载和保存一次。
- 后续同 SPU 任务复用已保存的主图，并在结果中标明“复用”。

如果页面仍出现多个候选主图，取“商品信息”区域的首张主图，并在结果中记录候选数量供复核。

### 6.3 重复运行规则

- 目录已存在时复用，不删除原有内容。
- 目标图片已存在且校验通过时跳过下载。
- 同一批中相同 SPU 只生成一张主图文件。
- 同名文件内容不同不得静默覆盖，应增加序号或写入异常报告。
- 每次运行生成单独的 CSV/XLSX 结果文件，包含时间、SPU、货号、SKC、目录、保存结果、下架结果和错误信息。

## 7. 标准业务流程

### 7.1 导入和预检

1. 用户在“图片/视频更新任务全球”页面内的悬浮面板中导入 SPU Excel，或直接粘贴 SPU ID 后加入任务列表。
2. 扩展读取并校验 SKC、货号和重复行。
3. 显示待处理数量、货号、目标浏览器名称与 ID、下架原因和固定输出根目录。
4. 用户点击“开始处理”；首版建议提供“只保存图片，不下架”的演练开关。
5. 离开该页面时面板自动隐藏；返回该页面时自动恢复。
6. 拖动面板标题栏可以改变位置；最小化后保留当前皮肤和位置。

### 7.2 连接比特浏览器

1. 调用本地 API 打开指定浏览器 ID 对应的窗口。
2. 核验返回的 `seq`、`name` 和浏览器 ID。
3. 找到 Temu 商家后台页面；必要时打开目标页面。
4. 检测登录状态。未登录或出现验证码时暂停整批任务，并提示人工处理。

默认不调用比特浏览器 API，直接操作当前已经打开的 Temu 页面。BitBrowser ID 只放在默认折叠的高级设置中，需要主动打开指定窗口时才使用。

### 7.3 逐个处理 SPU

对 Excel 中每一行依次执行：

1. 打开“商品管理 → 图片/视频更新任务全球”。
2. 自动切换到“全部”任务栏，避免默认“待更新”栏造成漏查。
3. 将查询类型设为 SPU，逐个输入当前 SPU ID。
4. 点击“查询”，等待目标 SPU 的搜索结果完成。
5. 从商品信息中读取 SPU 和货号；页面货号与插件货号不一致时停止本行并提示。
6. 从素材信息中确认完整 SKC ID。
7. 在用户选择的父目录或浏览器下载目录中创建“下架图片合集 → 货号分类”目录，以及其中的“主图保存”和“背面图保存”目录。
8. 按 SPU 检查主图是否已保存；未保存时下载商品信息中的主图原图，校验后保存到“主图保存”。
9. 不对“背面图保存”执行任何自动下载或文件修改。
10. 打开页面中的官方客服/智能客服入口。
11. 输入或点击“商品下架”。
12. 点击“发商品”，等待“发送下架商品信息”表单。
13. 填写完整 SKC ID，原因选择“亏损下架”。
14. 点击“申请下架”。
15. 阅读二次确认提示；只有操作员已授权该批任务时才点击最终确认。
16. 等待平台返回新的客服结果。
17. 进一步到商品列表按 SKC 查询，核验商品是否进入“已下架/已终止”。
18. 记录本行结果，再处理下一条。

### 7.4 重试失败项

- “重试失败项”按钮自动统计可重试数量。
- 只重试“未查到、超时、处理失败、下架失败”。
- 成功项、重复项和“需复核”项不参与自动重试。
- 重试沿用当前保存目录、皮肤、处理模式和下架授权设置。

### 7.5 超时跳过

- SPU 查询、图片下载、浏览器下载、下架提交和结果核验分别设置超时上限。
- 查询和图片阶段超时后标记“超时已跳过”，继续下一行。
- 下架提交阶段超时后标记“超时已跳过（需复核）”，不自动重复提交。
- 超时后刷新工作页面，清理卡死的页面状态。
- 超时参数可在高级设置中调整，并提供上下限校验和恢复默认值。

## 8. 图片需求

### 8.1 主图

当前已确认：

- 来源为“图片/视频更新任务全球”列表目标行的商品信息缩略图。
- 页面缩略图 URL 带有裁剪参数，保存时应移除裁剪参数并下载原图。
- 当前 SPU 主图原图大小为 `1340 × 1785` 像素，格式为 JPEG。
- 当前 SPU 只有 1 张明确的主图。
- 多色值商品改为保存轮播图分组第一张图。
- 默认保存商品信息中的普通主图原图。
- 批次可勾选“是否为多色值商品”。
- 勾选后保存第一个轮播图分组中的第一张原图；轮播图未找到时才回退到普通主图。
- 结果表记录图片来源，取值为“普通主图”或“轮播图”。

保存前应校验：

- HTTP 状态成功。
- 内容类型为图片。
- 图片能够被解码。
- 宽高大于业务最低阈值。
- 文件非 HTML 错误页或零字节文件。

### 8.2 背面图

背面图是每个货号可复用的模板资源。程序只要求创建空目录：

- 不进入商品页面下载背面图。
- 不根据图片序号推导背面图。
- 不写入、移动、重命名或覆盖已有背图模板。
- 目录已存在时直接复用。
- 目录不存在时创建空目录。

## 9. 下架需求

- 下架原因首版固定为“亏损下架”。
- 表单中的“商品ID”类型选择为“SKC ID”。
- 必须填写完整 SKC ID，不能截断或混入货号。
- 下架前展示 SPU、货号、SKC 和原因的核对窗口。
- 最终确认框明确提示下架可能无法再次上架，属于高风险操作。
- 默认建议开启“提交前人工确认”；用户确认后，可允许整批无人值守提交。
- 平台返回“系统忙碌”时不得标记成功，应记录失败并进入有限次数重试。

### 9.1 待发布商品删除

- 新增“删除待发布商品并保存主图”处理模式。
- 必须先完成图片保存，再进入商品列表执行删除。
- 商品列表切换到“未发布到站点”，查询类型设为 SPU。
- 按 SPU 查询后，逐个删除该 SPU 下的全部 SKC。
- 每个 SKC 使用“删除 → 确认删除”，删除后确认该 SPU 不再出现在待发布列表。
- 删除模式必须单独勾选授权，并在开始前再次确认。
- 收到“该商品已下架”后仍需通过商品列表二次核验。

当前平台二次确认原文包含：

> 商品下架后，可能因各类因素影响而无法再次上架销售，造成不可逆的损失。

因此扩展不得在用户不知情的情况下自动确认下架。

## 10. 结果状态

每个 SPU 建议使用以下状态：

| 状态 | 含义 |
|---|---|
| 待处理 | 已导入，尚未执行 |
| 处理中 | 正在查询、下载或提交 |
| 下架成功 | 客服回复成功且商品列表核验通过 |
| 图片成功、下架失败 | 图片已归档，但下架未完成 |
| 平台处理中 | 已提交，平台尚未返回明确结果 |
| 需人工确认 | 主图冲突、页面货号与插件货号不一致等 |
| 失败可重试 | 网络、临时超时、系统忙碌 |
| 失败不可重试 | 商品不存在、SKC 不匹配、无权限等 |

## 11. 异常处理

- 浏览器未启动、API 不可用：停止批次并提示检查比特浏览器。
- 浏览器 ID 不存在：不按序号猜测其他窗口。
- 页面未登录：停止批次并保留进度。
- 搜索无结果：记录“SPU 不存在或当前店铺无权限”，继续下一条。
- 搜索结果多个：暂停并人工选择，禁止静默取第一行。
- SKC 为空或格式异常：不提交下架。
- 图片下载失败：重试有限次数；仍失败则记录。
- 下架表单未出现：重新执行“商品下架 → 发商品”，最多重试 2 次。
- 页面结构变化：停止后续任务并提示维护选择器，避免错误点击。
- 平台提示系统忙碌：等待后退避重试，默认最多 3 次。
- 成功消息与商品列表状态不一致：标记“需人工复核”，不重复提交。

## 12. 验收标准

以下条件全部满足才能视为首版通过：

1. 能读取 Excel 并按顺序处理。
2. 未填写 BitBrowser ID 时直接操作当前 Temu 页面；填写后能正确打开指定窗口。
3. 能在用户选择的父目录或浏览器下载目录中创建正确目录结构。
4. 能保存原图而非缩略图，并通过尺寸与文件完整性校验。
5. 能按 SPU 查询并准确提取货号、SKC 和主图原图；页面货号与插件货号一致。
6. 能完成 SKC 下架表单填写并识别平台结果。
7. 能区分成功、系统忙碌、无结果和页面异常。
8. 能在商品列表“已下架/已终止”中核验成功项。
9. 中断后能够继续未完成项，已完成项不会重复提交。
10. 程序不会自动修改“背面图保存”目录中的已有模板。
11. 全程不记录或导出账号密码、Cookie 等敏感信息。

## 14. 已确认事项

1. 目录结构确认为：

```text
用户选择的父目录/下架图片合集/{货号分类}/主图保存
用户选择的父目录/下架图片合集/{货号分类}/背面图保存
```

2. 货号分类由页面货号自动提取，例如 `CXTX9 → CXTX`；插件保留可选人工覆盖值。
3. 一张 Excel 可以包含多个货号分类，程序按每行查询结果自动分组。
4. Excel C 列“状态”采用导出新结果表的方式写入，不修改原文件。
5. 表内状态为成功的行默认跳过；其余 SKC 全部按行处理。
6. 每个 SPU 只保存一张主图，同批多个 SKC 对应同一 SPU 时复用主图。
7. 主图出现多个候选时取“商品信息”区域的首张主图。
8. 采用纯 Chrome MV3 扩展，不依赖本地助手、Native Messaging 或固定本机端口。
9. 默认模式为“只保存主图，不下架”。
10. 真实下架必须勾选最终授权，并在开始前再次确认。
11. 平台返回系统忙碌时最多重试 3 次，间隔 15 秒。
12. 支持一键重试可重试失败项，并避免重复处理成功项。
13. 单行操作超时后可跳过并继续后续任务，不导致整批卡死。
